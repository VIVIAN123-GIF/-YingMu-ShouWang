# P03 评价口径 v1.0

状态：`FROZEN`。本文件与 `p03-evaluation-spec.v1.json` 共同定义 P03 正式报告口径；机器规范优先用于自动校验和计算。

## 1. 声明边界

P03 只验证三名健康成年参与者受控素材上的工程行为，不代表临床灵敏度、特异度、跌倒概率或老年人群泛化能力。`RISK_PRECURSOR` 只保留为旧拍摄动作标签，不再作为 ORANGE 真值。

正式主结果仅使用完整系统 `config_id=A`。B-D 消融配置尚无可执行实现，不得进入 P03 正式结果。P03 仅做描述性报告，不设置效果指标的 PASS/FAIL 阈值。

## 2. 两条评价轨

即时事件轨只评价一次有效坐站转换后的不稳 Evidence、独立信号族及 v1.2 裁决。`POS_RAPID_RISE_SWAY` 是人工不稳正样本，但人工动作不直接等同于“两个算法信号族”或 ORANGE 真值。

步态/趋势轨评价慢速小步、步幅不对称和正常行走中的 Evidence、工程指数与降级情况。它不参与即时 ORANGE Accuracy，也不得因无坐站转换而创建 ORANGE RiskEvent。

| 场景 | 角色 | 主要报告项 |
|---|---|---|
| `POS_RAPID_RISE_SWAY` | 即时不稳正样本 | 转换、至少一族、至少两族、ORANGE产出、片内窗口 |
| `NEG_RAPID_RISE_STABLE` | 即时稳定对照 | 允许起身速度观察；禁止ORANGE |
| `NEG_NORMAL_RISE_WALK` | 即时门控对照 | 允许不可判定；禁止ORANGE，不算GREEN真负 |
| `POS_SLOW_SMALL_STEP_SWAY` | 步态趋势目标 | `relative_speed_change`、`gait_instability` 任一及分别检出 |
| `POS_ASYMMETRIC_STEP` | 步态趋势目标 | `gait_instability`，按方向分层 |
| `NEG_BOUNDARY_NORMAL` | 门控/降级 | 无转换、遮挡/出画降级及禁止ORANGE |
| 正常行走基线4段 | 趋势参考 | 异常步态Evidence误检和指数参考；不是独立测试集 |

## 3. 固定指标

即时轨分别报告有效转换检出率、不稳信号族检出率、多信号族形成率、ORANGE产出率、其余20段评测片段的禁止ORANGE事件率、裁决覆盖率、覆盖片段中的规则一致率和窗口命中率。足部 `support_base_change` 与 `compensatory_step` 同时出现仍只算一个族。

窗口指标只能使用执行器输出的正式片内时间戳。已检出 Evidence 缺少正式片内时间戳时，窗口指标整体为 `NOT_AVAILABLE`，不得人工推测或补写。

机器结果以 `p03-inference-results/1.0` 为唯一正式来源：每条 Evidence 必须携带唯一 `evidence_id`、连续 `ingestion_order`、片内 `timestamp_ms`、`severity` 和质量字段；每段必须保留与入库顺序一一对应的完整 `rule_traces`。裁决一致性由分析器按冻结的 v1.2 规则重放 RuleTrace 判定，不使用手工 `predicted_label` 或单一汇总状态。

趋势轨按场景报告目标 Evidence 的分子、固定分母和 Wilson 95% 区间。工程指数报告原始值、中位数和 IQR；只用 `VALID/PARTIAL` 快照计算预声明中位数差，任一组少于2段时写 `NOT_ESTIMABLE`。不做显著性检验。

模块失败、缺失结果、质量不足和 `INSUFFICIENT` 均保留在原始分母内，不得排除或插补。GAIT/TRAJECTORY 状态、评估状态、基线状态和降级原因必须分别计数。

## 4. 解封条件

P03 的32段锁定素材、人工标签和事件区间必须先于推理完成。正式执行器须先在 P01/P02 全量演练，并证明结果完整、幂等且不覆盖旧结果。最终冻结文件必须绑定 P03 lock、v1.2、v1.3-min、模型、评价规范、本文和执行器的 SHA-256。

P03 使用隔离实验数据库；每个评测片段从同一冻结基线状态开始。结果根节点必须记录脱敏 `database_isolation_id` 和同一个 `baseline_seed_sha256`。正式运行后不得调阈值、改标签、筛样本或选择性重跑。基础设施失败只能按预先定义的重试流程执行，并保留全部尝试记录。

正式结果根节点必须包含 `execution_id`、带时区 `generated_at` 和规范化记录的 `records_sha256`；每段必须保留按顺序排列的 `attempts`。分析器会拒绝摘要哈希不符的常规手工改动。该哈希用于完整性检查，不构成数字签名或身份认证。

当前协议每名参与者只有一个基线日期，预期 `baseline_status=INSUFFICIENT`，不得宣称完成个体化基线验证。
