# “萤目守望”心理趋势与诈骗核验最小现场拍摄方案

受限人员与晚间执行版 v1.0｜现场人员：3人｜单次可用时间：2-3小时｜正式源视频：8段

> 本方案取代39段推荐验证版作为当前可执行方案。目标是用最少的真实授权录像证明视频、音频、Observation、Evidence和页面闭环可以运行，再用明确标记为`MOCK`的结构化场景补充规则边界覆盖。它不支持心理疾病识别准确率、真实诈骗识别准确率或三条研究方向同等成熟的结论。

## 1. 方案结论

### 1.1 实际拍摄量

| 方向 | 正式视频 | 净录像时长 | 现场占用 | 作用 |
|---|---:|---:|---:|---|
| 心理趋势 | 3段 | 4.5分钟 | 约25分钟 | 验证区域活动、活动下降和恢复的轨迹提取 |
| 诈骗核验 | 5段 | 8.75分钟 | 约65分钟 | 覆盖正常、单证据、双证据和三证据组合 |
| 冒烟小样 | 1段，不计正式结果 | 30秒 | 约10分钟 | 开拍前检查机位、轨迹和收音 |
| 质检、补拍、备份 | - | - | 约50分钟 | 确保素材能用 |

正式视频共8段，净录像时长约13分15秒。包含准备、换角色、台词预演、质检和一次补拍缓冲后，一次2.5小时晚间拍摄可以完成。

### 1.2 能满足什么

- 验证授权C6c录像可以进入`TRAJECTORY`或`LANGUAGE`适配器；
- 验证心理趋势的客观区域活动Observation可以从真实录像产生；
- 验证代表性诈骗脚本可以产生访客、停留和关键词Evidence；
- 验证本次代表性困难负样本没有错误升级到橙色；
- 验证一条组合风险事件可以由家属核验后进入回落流程；
- 在演示视频中提供真实授权录像，而不是全部使用固定JSON。

### 1.3 不能满足什么

- 不能报告真实心理健康识别准确率；
- 不能报告真实诈骗案件识别准确率；
- 不能把3段心理视频描述成真实多日连续监测；
- 不能把5段诈骗视频描述成具有统计代表性的真实案件测试集；
- 不能将结构化`MOCK`场景和真实录像合并计算一个准确率。

## 2. 三人分工

| 人员 | 主要角色 | 心理拍摄时 | 诈骗拍摄时 |
|---|---|---|---|
| A | 导演、设备、台账 | 控制C6c、报场次、计时、检查文件 | 同左，兼后台授权名单状态记录 |
| B | 居家人员演员 | 完成正常、下降和恢复行为 | 扮演居家人员R |
| C | 访客演员兼安全员 | 在镜头外观察路线和身体状态 | 扮演授权访客V-A和未登记访客V-U |

诈骗场景没有危险动作，C可以参与表演。心理场景由C站在镜头外负责安全观察。A不出镜，导演口令尽量在正式动作前完成，最终素材只保留必要环境声和授权台词。

## 3. 拍摄前必须完成

### 3.1 授权与隐私

- B、C必须签署视频与声音采集授权；A的声音若被保留，也应纳入授权。
- 授权中明确包含受控访客演绎、虚构诈骗台词、脱敏语音转写和比赛演示用途。
- 不使用真实老人、真实心理疾病经历、真实诈骗受害经历或真实家庭关系。
- 不出现真实姓名、地址、电话、单位、银行卡、二维码、验证码和支付页面。
- 原始视频保存于Git之外的受控目录，设置保存截止日期和撤回方式。

### 3.2 设备与场地

- 同一台C6c，固定H.264，建议1920×1080、25或30 FPS。
- 关闭云台跟随、巡航、数码变焦。
- 所有素材统一填写`lighting=INDOOR_NIGHT`，不要把晚间拍摄伪装成真实日间数据。
- 地面标记`doorway(D)`、`living_room(L)`、`corridor(C)`三个区域。
- B、C全身和双脚在主要动作阶段可见。
- 关闭电视和音乐；手机进入飞行模式且不显示私人页面。

### 3.3 文件命名

```text
MIN-MENTAL-NORMAL-01.mp4
MIN-MENTAL-DECLINE-01.mp4
MIN-MENTAL-RECOVERY-01.mp4
MIN-FRAUD-AUTH-NORMAL-01.mp4
MIN-FRAUD-UNKNOWN-BRIEF-01.mp4
MIN-FRAUD-AUTH-KEYWORD-01.mp4
MIN-FRAUD-UNKNOWN-DWELL-01.mp4
MIN-FRAUD-COMBINED-01.mp4
```

所有正式视频统一记录：

```text
source_mode=RECORDED_REPLAY
simulated=true
camera_position_id=living-room-c6c-v1
scene_config_id=scene-living-room-v1
authorization_record_ids
expected_evidence
maximum_expected_level
validity
sha256
```

## 4. 一次晚间拍摄排期

以下以19:00开始为例，总占用约2.5小时。

| 时间 | 工作 |
|---|---|
| 19:00-19:20 | 授权确认、区域胶带、机位、收音和隐私检查 |
| 19:20-19:30 | 1段冒烟小样并立即回看 |
| 19:30-19:55 | 3段心理视频，包含一次补拍缓冲 |
| 19:55-20:25 | 前3段诈骗视频，短暂停留和关键词场景 |
| 20:25-20:45 | 未登记访客长停留场景 |
| 20:45-21:10 | 三证据组合场景 |
| 21:10-21:25 | 每类抽查、必要补拍 |
| 21:25-21:30 | 双份备份并核对8段正式文件 |

如果19:20的冒烟小样不通过，不继续批量拍摄。先调整区域、光照和收音；当晚无法修复时只保留测试文件，不勉强完成正式素材。

## 5. 冒烟小样：30秒

文件名：`MIN-SMOKE-01.mp4`，不计入8段正式素材。

```text
0-5秒    空画面
5-15秒   B从D进入L，再从L走到C
15-25秒  C进入L，和B说：“这是虚构测试，请先联系家属核验。”
25-30秒  两人停稳
```

开拍门禁：

- MP4可以完整播放，编码、分辨率和FPS正确；
- D、L、C区域判断与实际位置一致；
- 轨迹适配器能输出至少一条区域或活动Observation；
- 两人的声音可以听清，转写不是空文本；
- 画面和输出中没有私人信息、设备序列号或绝对路径。

## 6. 心理趋势：3段真实视频

### 6.1 `MIN-MENTAL-NORMAL-01`：正常多区域活动，90秒

目的：验证正常区域活动和多次转换。

```text
0-5秒    空画面
5-15秒   B从D进入L
15-30秒  在L整理空白文件夹或拿放水杯
30-42秒  L到C
42-54秒  C回L
54-66秒  L到D
66-78秒  D回L
78-87秒  在L自然停留
87-90秒  保持
```

人工预期：访问3个区域，至少4次有效转换；不产生心理风险结论。

### 6.2 `MIN-MENTAL-DECLINE-01`：单一区域低活动，90秒

目的：验证区域活动下降的客观输入，不表演抑郁或认知障碍。

```text
0-5秒    空画面
5-15秒   B从D进入L
15-35秒  在L坐下或安静整理物品
35-55秒  在L站起，移动1-2步，不跨区
55-75秒  继续停留在L，完成轻微自然动作
75-85秒  从L走向D
85-90秒  空画面
```

人工预期：主要停留在1个区域，区域转换少于正常片段。

### 6.3 `MIN-MENTAL-RECOVERY-01`：恢复正常活动，90秒

该段与`DECLINE`分开录制，不能直接复用正常片段冒充恢复。

```text
0-5秒    空画面
5-15秒   B从D进入L
15-27秒  L到C
27-39秒  C回L
39-51秒  L到D
51-63秒  D回L
63-75秒  L到C再返回L
75-87秒  在L自然活动并停稳
87-90秒  保持
```

人工预期：区域数和转换恢复到正常片段的范围。

### 6.4 多日趋势如何补齐

不再拍摄“日间”和“夜间”视频，也不要求连续拍7-8天。另行生成12组明确标记为`MOCK`的日汇总JSON：

| 类型 | 组数 | 输入 |
|---|---:|---|
| 正常波动 | 3 | 7日稳定基线+第8日接近基线 |
| 活动下降 | 3 | 7日稳定基线+第8日区域和转换下降 |
| 节律变化 | 3 | 7日稳定基线+第8日昼间活动比例偏移 |
| 下降后恢复 | 3 | 第8日下降+第9日恢复 |

这12组只验证趋势算法和规则边界。报告必须把3段真实录像和12组`MOCK`趋势分别列出，不合并计算。

## 7. 诈骗核验：5段真实视频

### 7.1 `MIN-FRAUD-AUTH-NORMAL-01`：授权访客正常交流，60秒

台账人工标记：`visitor_authorized=true`。

```text
0-5秒    空画面
5-15秒   C以V-A身份从D进入L
15-42秒  C：“我来送上次借的书，顺便通知下周有普通活动。”
          B：“好的，我知道了，谢谢。”
42-52秒  C离开L进入D
52-60秒  空画面
```

预期：无诈骗风险Evidence，无风险事件。

### 7.2 `MIN-FRAUD-UNKNOWN-BRIEF-01`：未登记访客短暂停留，60秒

台账人工标记：`visitor_authorized=false`。

```text
0-5秒    空画面
5-15秒   C以V-U身份进入L边缘
15-35秒  C：“您好，我可能走错门了，请问出口在哪里？”
          B：“从走廊向右走。”
35-50秒  C主动离开
50-60秒  空画面
```

预期：允许`unauthorized_visitor`；不得产生`unusual_dwell_time`和`fraud_keyword`；最高不超过黄色核验提示。

### 7.3 `MIN-FRAUD-AUTH-KEYWORD-01`：授权访客风险词困难负样本，75秒

台账人工标记：`visitor_authorized=true`。

```text
0-5秒    空画面
5-15秒   C以V-A身份进入L
15-50秒  C：“新闻提醒，任何人索要验证码都不能告诉他，正规的投资也不会保证收益。”
          B：“知道了，涉及转账我会先联系家里人。”
50-65秒  C离开
65-75秒  空画面
```

预期：允许产生低置信`fraud_keyword`；因访客已授权且没有长停留，不得进入橙色。

### 7.4 `MIN-FRAUD-UNKNOWN-DWELL-01`：未登记访客长停留、无风险词，150秒

台账人工标记：`visitor_authorized=false`。必须连续录制，不剪辑、不循环、不加速。

```text
0-5秒     空画面
5-15秒    C进入L
15-125秒  两人围绕天气、普通兴趣和公共活动自然交流；不得说转账、验证码、收益、付款等风险词
125-140秒 B：“我暂时无法确认身份，请先离开，我会联系家属。”
140-150秒 C离开L进入D
```

预期：允许`unauthorized_visitor`和`unusual_dwell_time`；没有`fraud_keyword`；最高不超过黄色核验提示。

### 7.5 `MIN-FRAUD-COMBINED-01`：三证据组合，180秒

台账人工标记：`visitor_authorized=false`。使用虚构金额、虚构验证码，不展示任何真实支付页面。

```text
0-5秒      空画面
5-15秒     C进入L
15-120秒   C使用空白文件夹介绍虚构“养老服务”，保持自然交流和长停留
120-155秒  C：“这个虚构项目保证收益，今天马上办理，请先转一笔虚构定金，验证码填000000。”
155-170秒  B：“我不会现在操作，我要先联系家属核验。”
170-180秒  C离开或在D区域等待
```

预期：`unauthorized_visitor + unusual_dwell_time + fraud_keyword`齐全，进入`ORANGE/INTERVENING`，但页面不得显示“已确认诈骗”。

录像完成后录制一段屏幕操作，不增加摄像机拍摄量：

```text
进入事件详情
查看三类Evidence及来源标签
选择“已联系老人/完成身份核验”
写入identity_verified或false_alarm_confirmed
确认事件进入观察或解除
```

## 8. 结构化模拟场景如何补边界覆盖

在5段真实诈骗素材之外，再生成12组结构化`MOCK`场景，不增加现场拍摄：

| 类型 | 组数 | 目的 |
|---|---:|---|
| 授权访客+正常对话 | 2 | 正常控制 |
| 未登记访客+短停留 | 2 | 单访客Evidence边界 |
| 授权访客+风险词 | 2 | 单关键词困难负样本 |
| 未登记访客+长停留、无风险词 | 2 | 双Evidence困难负样本 |
| 未登记访客+长停留+风险词 | 2 | 组合正向场景 |
| 组合场景完成家属核验 | 2 | 事件回落与幂等 |

12组模拟场景使用脱敏行为摘要和授权转写文本，不复制真实视频冒充新样本。报告必须分别写：

```text
真实授权录像：心理3段、诈骗5段，用于媒体链路和代表性功能验证。
结构化模拟场景：心理12组、诈骗12组，用于规则覆盖、困难负样本和状态回落验证。
两类结果按来源分别报告，不合并为准确率。
```

## 9. 最小方案的统计口径

### 9.1 真实录像只报告原始计数

```text
心理真实录像轨迹提取成功数 / 3
诈骗真实录像预期Evidence一致数 / 5
真实录像Evidence Schema与Observation追溯完整数 / 全部真实录像Evidence数
组合场景页面闭环完成数 / 1
```

样本数太小，不建议只写百分比。例如写“5/5段完成预期工程流程”，不要写“准确率100%”。

### 9.2 模拟场景报告规则覆盖

```text
心理正向模拟场景触发数 / 9
心理正常模拟场景错误触发数 / 3
心理恢复模拟场景闭环数 / 3
诈骗组合模拟场景橙色触发数 / 2
诈骗非组合模拟场景错误橙色触发数 / 8
诈骗核验模拟场景闭环数 / 2
```

报告名称使用“结构化模拟场景规则覆盖结果”，不能使用“真实识别准确率”。

## 10. 每段拍完立即检查

- [ ] 文件可播放，文件名和角色正确。
- [ ] 分辨率、FPS、H.264和机位未变化。
- [ ] 人物全身、D/L/C区域和主要动作可见。
- [ ] 长停留素材连续达到时长要求。
- [ ] 正常场景没有误说风险词。
- [ ] 风险场景台词清晰，全部是虚构信息。
- [ ] 无未授权人员、真实账号、私人屏幕或门牌入镜。
- [ ] 人工预期在查看算法结果前填写。
- [ ] `source_mode=RECORDED_REPLAY`、`simulated=true`。
- [ ] 主存储和第二份备份均已写入。

算法漏检、误报或结果不理想不是补拍理由。只有文件损坏、人物出画、区域错误、时长不足、台词说错、收音不可用或隐私违规才补拍。

## 11. 剩余工程工作量

拍摄完成不等于验证完成。当前仍需：

| 工作 | 估计开发/处理时间 |
|---|---:|
| 冻结心理和诈骗规则，补按风险域分派 | 0.5-1开发日 |
| 增加`trend_recovered`和诈骗核验回落 | 0.5开发日 |
| 生成心理12组、诈骗12组结构化场景 | 2-3小时 |
| 批量运行、幂等复跑和统计 | 3-5小时 |
| 页面截图、屏幕录制和报告更新 | 2-3小时 |

只有一个晚间2-3小时但没有后续开发和处理时间时，应把心理、诈骗保留为演示扩展，不报告闭环统计。

## 12. 最终对外表述模板

```text
项目以跌倒风险前置预警作为主要实测方向。
心理趋势和诈骗核验作为统一Evidence架构的扩展验证：
团队使用8段健康成年人授权模拟录像验证真实媒体处理与代表性功能链路，
并使用24组明确标记的结构化模拟场景验证多日趋势、困难负样本、
多证据组合和反馈回落规则。相关结果属于工程场景验证，
不构成心理疾病诊断、真实诈骗案件识别或临床/司法结论。
```

该口径与当前人员、时间和系统成熟度匹配，也能避免把少量真实录像包装成性能数据。
