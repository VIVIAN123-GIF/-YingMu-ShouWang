# 老师意见总结与后续行动方向


## 一、老师意见总结

### 1.1 核心矛盾：覆盖广度 vs 聚焦深度

| 老师的原话 | 深层含义 |
|-----------|----------|
| “给你三个问题你必须三个问题都兼顾并融合” | **不能放弃任何方向**——比赛要求三大方向，缺一不可 |
| “计算机学院揭榜应该是提出一个通用的方法去解这个问题” | 评分体系期待的是**技术范式**（一个通用的方法框架），而非“硬件堆砌+模块拼凑” |
| “预警的‘预’是核心卖点” | 评委会对“‘预’是怎么做到的”最感兴趣——它必须从技术底层有说服力 |
| “基于一个任务做出预，然后其他故事能加一起加一起” | 用一个核心任务（跌倒）建立“预警范式”（通用方法），然后把心理和诈骗作为**应用场景**挂在这个范式上，而不是做三个独立的系统 |

### 1.2 具体问题

| 老师意见 | 说明 |
|----------|------|
| **“故事线不行，产品就不好卖”** | 方案缺乏清晰的、打动人的叙事逻辑，评委听完记不住 |
| **“时间把控，倒推”** | 8月31日前必须完成，需要倒推每周目标 |
| **“组员积极性”** | 这是一个可能的风险点——不能所有人都等着别人做 |
| **“研究生配合代码，但故事设计主要靠你们”** | 不要依赖老师/研究生帮你们想“做什么”，他们只解决“怎么做” |
| **“先做好一个产品经理”** | 你需要负责产品定义、场景设计、故事线构建，而不是过早陷入技术细节 |

### 1.3 参考文件的核心启示

| 维度 | 核心要点 |
|------|----------|
| **故事线** | “痛点叙事”——从“事后诸葛亮”到“事前按中止键” |
| **三线叙事** | 故事线（打动人心）+ 应用线（产品怎么用/怎么卖）+ 技术线（学术深度） |
| **长中短三线场景** | 长期（3个月前：无感筛查）+ 中期（昨夜：动态防御）+ 短期（黄金半分钟：安全着陆） |
| **应用线 vs 技术线** | 应用线是“皮”（用户看得见的交互），技术线是“骨”（支撑交互的算法和数据流）——答辩时必须区分清楚 |


## 二、后续努力方向

### 方向一：建立“通用预警范式”的技术叙事

**核心逻辑**：技术创新的核心是“**多模态微特征连续观测→个人基线建模→异常趋势预警**”这一通用框架。心理和诈骗不再是自己有一套独立逻辑，而是作为这个通用框架的两个附加应用场景，挂在跌倒的主线上。

| 方向 | 在通用框架中的角色 | 如何融入 |
|------|-------------------|----------|
| **跌倒风险** | **主场景**，建立预警范式的核心 | 步态微特征 + 环境微特征 + 个人基线 |
| **心理健康** | 通用框架在“长期行为趋势变化”维度的**附加应用** | 活动量下降、社交减少作为“微特征”输入，通过同一套“长期趋势变化检测”逻辑预警 |
| **诈骗识别** | 通用框架在“外部事件触发”维度的**附加应用** | 陌生人停留、异常语音关键词作为“事件特征”输入，通过同一套“时空耦合判断”逻辑预警 |

**技术答辩的核心一句话**：

> “我们提出了一种基于多模态微特征连续观测与个人基线建模的通用预警范式，并以跌倒风险为主应用场景验证其有效性——心理健康和诈骗风险作为该范式的附加应用场景，证明了框架的可扩展性。”

### 方向二：重构三线叙事（产品经理思维）

| 线 | 做什么 | 交付物 |
|----|--------|--------|
| **故事线** | 用“张爷爷的100天”建立情感共鸣，回答“为什么做” | 4-6页故事PPT（配图、配场景描述） |
| **应用线** | 展示产品形态、交互流程、商业闭环，回答“怎么用/怎么卖” | 应用场景图、设备部署图、交互流程图 |
| **技术线** | 展示算法框架、数据流、创新点，回答“怎么实现” | 五步判断流程图、技术架构图 |

**故事线结构（长中短三线）** ：

| 时间线 | 内容 | 技术对应 |
|--------|------|----------|
| **长期（3个月前）** | 系统无感筛查，发现张大爷步态微变化（拖步、起夜频繁） | 长时程监测 + 个人基线 |
| **中期（昨夜）** | 系统判断“今夜高危”，自动调低预警阈值 | 动态风险地图 + 趋势分析 |
| **短时（黄金半分钟）** | 张大爷起夜匆忙，系统开灯+语音提醒，避免跌倒 | 实时推理 + 低延迟干预 |

**应用线：产品怎么卖**

| 应用场景 | 卖点 |
|----------|------|
| 子女远程看护 | 不是“出事才通知”，而是“提前发现苗头”——子女不用时刻盯着App，系统主动预警 |
| 社区养老服务中心 | 一套系统覆盖多户老人，降低人力巡检成本 |
| 适老化改造服务商 | 预警数据可以转化为“居家环境改造建议”，形成服务闭环 |

> **“老师要求我们用‘产品经理’的思维来设计这个项目——先把‘为什么要做、给谁用、怎么卖’想清楚、讲漂亮（故事线+应用线），再想‘技术怎么做’（技术线）。三大方向不是做三个独立系统，而是用一个‘多模态微特征连续观测+个人基线建模’的通用范式去覆盖三个应用场景，用一个核心任务（跌倒）把‘预警的预’讲透，心理和诈骗作为附加应用场景挂在这个范式上，以此实现‘三个问题都兼顾并融合’的要求。”**
