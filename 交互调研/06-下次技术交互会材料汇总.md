## 模块一：跌倒与步态算法（赵勇，2页）

## 第3页：跌倒前兆技术选型

| 环节 | 一期选择 | 暂不优先 |
|---|---|---|
| 人体姿态 | MediaPipe Pose | 训练大型姿态模型 |
| 输入 | 本地MP4、公开数据、后续C6c视频 | 一开始依赖实时流 |
| 特征 | 起身时长、躯干摇摆、相对步速、关键点连续性 | 端到端预测全部风险 |
| 判断 | 可解释规则/传统分类器 | LSTM仅作P1对照 |
| 输出 | Observation＋FALL Evidence | 算法直接输出绿黄橙红 |

最低输出：rapid_rise、slow_rise、trunk_sway、gait_instability、relative_speed_change、posture_recovered、tracking_lost，并携带severity、confidence和data_quality。

可行性：

- MediaPipe可先在普通PC形成关键点Demo；
- 固定机位有利于相对特征和区域标定；
- 公开数据可验证代码流程，但不能直接证明“跌倒前预警”；
- 前置风险仍需自采快速起身、摇晃和正常干扰场景。

风险与降级：

| 风险 | 降级 |
|---|---|
| 遮挡、低照度导致关键点丢失 | 输出tracking_lost和低data_quality，不自动升级 |
| 单目相机难以获得真实速度 | 使用相对速度＋固定机位标定 |
| LSTM数据不足 | 规则基线优先，LSTM延期 |
| 实机未到货 | 使用URFD、自录MP4和Mock Evidence |

会前补入：Demo截图/失败日志、稳定特征清单、3条Evidence、CPU速度与最大风险。

## 第4页：跌倒数据与验证

数据分工：

- URFD、SisFall：辅助动作识别、代码流程和干扰动作研究；
- 自采模拟实验：快速起身、摇晃、转身、伸懒腰、低照度；
- C6c实机：最终黄金半分钟和设备场景验证。

第一版计划：

- 不少于8名志愿者、96段前兆与正常干扰；
- 按参与者划分训练、验证和测试；
- 比较统一阈值与个人基线；
- 指标包括Precision、Recall、F1、每小时误报、高风险窗口召回和端到端延迟。

四组消融：

1. 统一阈值 vs 个人基线；
2. 只有短时Evidence vs 长中短融合；
3. 不使用data_quality vs 使用质量门槛；
4. 只判断提醒发出 vs 加入风险回落复核。

待确认：特征定义、样本规模、阈值校准、参与者划分和统计方法。

## 模块二：语音与行为算法（常易铭，2页）

## 第5页：行为轨迹和语音技术选型

| 子任务 | 一期方案 | 输出 |
|---|---|---|
| 人员/区域轨迹 | OpenCV检测/跟踪＋区域计时 | 活动范围、区域转换、访客停留 |
| 中文语音转写 | 本地Whisper小模型或量化模型 | 授权文本、音频质量 |
| 诈骗话术 | 关键词/短语＋访客和停留证据 | fraud_keyword Evidence |
| 心理趋势 | 活动/作息长期偏离＋人工反馈 | 最高自动YELLOW |

边界：

- 不根据语音流畅度诊断心理疾病；
- 不根据单个关键词触发诈骗橙色；
- 不读取陌生号码、不判断真实转账；
- 音频明确授权，优先本地转写和短时缓存；
- 心理、诈骗使用同一C6c集中拍摄的模拟回放。

风险与降级：

| 风险 | 降级 |
|---|---|
| Whisper在CPU上延迟高 | 小模型、短片段或预先转写 |
| 访客身份识别不可靠 | 人工标记授权/非授权访客 |
| 单机无法跨房间跟踪 | 只统计测试区域和可见范围 |
| 单关键词误报 | 访客、停留、话术多证据耦合 |

会前补入：Whisper模型与延迟、轨迹Demo/失败记录、3条Evidence、组合规则草案。

## 第6页：心理与诈骗Evidence适配

心理链路：

> 活动/作息持续偏离＋家属关怀或老人自述 → YELLOW周报 → 亲情联系/自愿筛查建议 → 趋势和反馈复核

候选Evidence：activity_range_decline、room_transition_decline、day_night_rhythm_change、family_concern、trend_recovered。

诈骗链路：

> unauthorized_visitor＋unusual_dwell_time＋fraud_keyword → ORANGE身份核验 → 家属确认/访客离开 → RESOLVED

待确认：

- 心理最低保留哪些行为，需持续几天；
- 如何排除天气、生病、旅行等干扰；
- 访客事件开始、结束和证据组合窗口；
- 心理最高自动YELLOW、诈骗最高自动ORANGE是否合理。

## 模块三：智能体与风险状态机（张薇，2页）

## 第7页：智能体技术架构

当前选择：

- 普通Python单智能体编排；
- MemoryStore保存30秒、24小时、7天以上窗口；
- 确定性RiskEngine和StateMachine决定安全等级；
- Policy选择批准的干预策略；
- ToolAdapter封装真实和Mock工具；
- 大模型只做解释、周报和复盘；
- 一期不引入复杂Agent框架。

固定闭环：

> Evidence → 个人记忆 → ruleset-v1.0 → RiskEvent → Policy/ToolAdapter → InterventionResult → OBSERVING → RESOLVED或ESCALATED

可行性：路径固定、工具少、普通Python便于调试和答辩解释；即使设备或算法未完成，也可用Mock Evidence联调。

风险与降级：

| 风险 | 降级 |
|---|---|
| 被认为只是普通规则系统 | 展示个人记忆、状态持续、工具编排和干预复核 |
| 规则初值缺少依据 | 标记工程初值，验证集校准并记录版本 |
| 大模型编造信息 | 字段白名单、结构化输出、事实检查、固定模板 |
| 工具调用失败 | 记录FAILED、重试一次、再使用明确标注的Mock |

## 第8页：个人基线、多时标融合与回落

当前默认：

- 个人基线：滚动中位数＋MAD；
- 冷启动：3天临时、7天初步稳定；
- 只有GREEN且质量合格的数据更新基线；
- 单条有效分暂定severity × confidence × data_quality；
- 30秒判断临近危险、24小时提供当天上下文、7天以上判断长期趋势；
- 跌倒橙色：30秒内快速起身＋躯干摇晃；
- 回落：15秒姿态稳定＋60秒无新危险观察。

以上均为待验证工程初值，不是既定科学结论。

希望确认三类结论：

1. 技术路线：单智能体、个人基线和多时标融合方法；
2. 规则与验证：橙色触发、风险回落和对照实验；
3. 能力边界：扩展Evidence和语音不可用时的降级演示。

# 第三部分：接口文档初稿（1页）

## 1. 数据流

~~~mermaid
flowchart LR
    S[C6c/回放/公开数据/Mock] --> D[DeviceAdapter]
    D --> ALG[MediaPipe/轨迹/Whisper]
    ALG --> O[Observation]
    O --> E[Evidence]
    E --> MEM[个人记忆]
    E --> RISK[RiskEngine/StateMachine]
    MEM --> RISK
    RISK --> RE[RiskEvent]
    RE --> TOOL[ToolAdapter]
    TOOL --> IR[InterventionResult]
    IR --> RISK
    RE --> API[FastAPI/SQLite]
    IR --> API
    API --> UI[Vue3统一时间轴]
~~~

## 2. 四个统一对象

| 对象 | 生产者 | 核心字段 | 消费者 |
|---|---|---|---|
| Observation | 感知算法 | id、time、source、feature、value、confidence、data_quality、source_mode | Evidence适配器 |
| Evidence | 算法/人工适配器 | evidence_id、domain、type、severity、confidence、quality、baseline、time_scale | 智能体 |
| RiskEvent | RiskEngine | event_id、risk_level、score、evidence_ids、action、status、ruleset_version | 前端、ToolAdapter |
| InterventionResult | ToolAdapter/家属反馈 | result_id、event_id、tool、delivery_status、response、risk_after、resolved | 状态机、前端 |

来源枚举：LIVE_DEVICE、RECORDED_REPLAY、PUBLIC_DATASET、MOCK。

## 3. 核心API

| 方法与路径 | 用途 | 负责人 |
|---|---|---|
| POST /api/v1/observations | 写入算法观测 | 冷雨彤 |
| POST /api/v1/evidence | 写入证据并触发评估 | 冷雨彤、张薇 |
| GET /api/v1/residents/{id}/baseline | 查询个人基线 | 张薇、冷雨彤 |
| POST /api/v1/risk/evaluate | 执行唯一风险判断 | 张薇 |
| GET /api/v1/events/{id} | 查询事件、证据和状态 | 冷雨彤 |
| POST /api/v1/events/{id}/intervene | 执行干预策略 | 张薇、冷雨彤 |
| POST /api/v1/events/{id}/results | 写入工具/恢复结果 | 冷雨彤 |
| POST /api/v1/events/{id}/feedback | 写入家属反馈 | 冷雨彤 |

## 4. 接口规则

- 时间使用含时区ISO 8601；分数0—1；缺失值用null；
- 算法只输出Evidence，不修改risk_level；
- ID和幂等键防止重复事件和重复播放；
- 低data_quality生成SYSTEM Evidence，不自动触发高等级；
- 工具失败写入FAILED并保留事件；
- 前端显示数据来源和模拟标识；
- 字段修改由张薇和冷雨彤共同确认并更新schema_version。

固定联调样例：

> rapid_rise＋trunk_sway → ORANGE/INTERVENING → 工具SUCCESS或FAILED → posture_recovered → OBSERVING → InterventionResult.resolved=true → RESOLVED
