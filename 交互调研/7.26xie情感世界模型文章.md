这篇文章和你们现在的项目方向高度契合。它最有价值的地方不是“具身机器人”，而是提出了一个更完整的居家养老逻辑：

> 系统不只是识别事故，而是理解老人生活状态的变化，并把变化交给正确的人完成处置。

这与“萤目守望”的个人基线、多时标记忆、分级干预和风险回落几乎是同一条思路。因此不需要推翻当前方案，而是可以用文章的观点补强你们的产品定义、心理故事线、责任链和实验指标。[文章：具身机器人进家，只差一套“情感世界模型”](https://m.sohu.com/a/1052989011_116132)

## 一、最值得借鉴：把系统定义为“家庭状态入口”

文章认为，养老设备不能只回答“发生了什么”，还要回答四个问题：

1. 老人现在正在做什么？
2. 与平时相比发生了什么变化？
3. 这种变化是否需要进一步确认？
4. 如果需要介入，应通知谁、由谁处置？

这四个问题可以直接对应你们的系统：

| 文章问题 | 萤目守望对应能力 |
|---|---|
| 现在做什么 | Observation：起身、摇晃、活动、访客、语音 |
| 与平时有什么变化 | 个人基线＋30秒、24小时、7天记忆 |
| 是否需要确认 | Evidence融合＋统一状态机 |
| 谁来介入 | 语音提醒、家属核验、人工接管 |
| 处置结果如何 | InterventionResult＋风险回落 |

你们汇报时可以把项目重新概括为：

> 萤目守望不是一台“检测跌倒的摄像机”，而是一个家庭状态入口：持续理解老人相对自身习惯的变化，在关键时刻连接老人、异地子女与人工服务。

但不要改成“情感世界模型”作为项目名称，因为你们没有机器人、情绪模型和完整服务网络。可以表述为：

> 我们参考“情感世界模型”对生活状态和责任关系的理解，在固定摄像机条件下实现一个可验证的“个人化居家预警范式”。

## 二、用“生活语义”补强心理故事线

文章明确指出，养老系统真正需要理解的不是简单的开心、难过等情绪标签，而是“生活语义”：

- 起床；
- 用餐；
- 活动；
- 外出与归家；
- 久坐；
- 夜间走动；
- 与家人的互动。

这正好能解决你之前觉得心理问题体现不足的问题。

你们不能只说：

> 张爷爷活动量下降，所以系统提示心理风险。

这样证据太单薄。可以改成：

> 连续阴雨后，系统发现张爷爷不仅活动范围缩小，而且起床时间推迟、客厅与厨房之间的活动减少、与家属的日常互动节奏发生变化。单项变化都不足以判断风险，但多项生活节奏连续偏离个人习惯后，系统将其放入黄色周报，建议女儿进行一次自然联系。

这样心理场景就从“活动量检测”升级为：

```text
生活行为序列
→ 与个人习惯比较
→ 多日趋势判断
→ 轻量确认
→ 家属反馈
→ 趋势回落或继续观察
```

同时继续保持边界：

- 不识别“抑郁表情”；
- 不诊断抑郁症或认知障碍；
- 不因为独居、丧偶直接判断心理问题；
- 只描述活动、作息和互动趋势。

## 三、增加“主动确认”，解决模型不确定性

文章提出一个很重要的产品逻辑：

> 当系统不确定时，不要直接下结论，而要通过轻量询问补充信息。

这可以成为你们智能体很有价值的一步。

### 跌倒场景

系统不是只播放警报，而是给出一个动作：

> “爸，别着急，先坐稳再走。”

之后继续观察是否恢复。

### 心理趋势

黄色周报后，由女儿自然联系：

> “爸，最近下雨是不是没怎么出去？身体还好吗？”

家属反馈可以形成新的确认信息：

```text
family_feedback
→ 老人表示只是下雨减少外出
→ 趋势得到解释
→ 保持观察或回落
```

### 诈骗场景

系统不直接宣称诈骗，而是发出核验建议：

> “检测到非授权访客长时间停留，并出现高风险交互特征，建议确认身份。”

确认结果再决定回落或人工接管。

因此，你们可以把闭环进一步表达为：

```text
观察 → 推断 → 轻量确认 → 干预 → 结果 → 风险修正
```

这比单纯的“识别—报警”更符合老师要求的预警范式。

## 四、补上目前较弱的“责任链”

文章最值得你们补充的部分，是“系统发现异常后谁负责”。

你们目前已经有老人、家属和智能体，但责任关系还可以讲得更清楚。

建议在交互PPT增加一张责任矩阵：

| 风险状态 | 系统责任 | 老人责任 | 家属责任 | 人工服务责任 |
|---|---|---|---|---|
| GREEN | 学习基线，不打扰 | 无需操作 | 查看摘要 | 不介入 |
| YELLOW | 整理趋势和原因 | 自愿反馈 | 联系老人、提交反馈 | 必要时提供专业建议 |
| ORANGE | 给一个明确动作、生成事件 | 坐稳或停止高风险动作 | 核验、联系老人 | 必要时人工接管 |
| RED | 保存证据、通知授权联系人 | 尽可能回应 | 立即确认 | 物业、社区或专业人员按授权处理 |
| RESOLVED | 记录结果、结束重复提醒 | 恢复正常活动 | 查看处置摘要 | 无需继续介入 |

一期不建议真的开发物业、社区端，也不要声称已经接入社区服务。可以在材料中写：

> 一期完成老人—家属责任闭环；物业、社区和专业服务机构作为未来经授权的人工承接角色。

## 五、增强家属端事件卡的表达

文章指出，家属需要的不是一句“发现异常”，而是四类信息：

- 系统观察到了什么；
- 与平时相比发生了什么变化；
- 为什么值得关注；
- 家属下一步应该做什么。

你们的事件卡可以统一成：

```text
系统观察
快速起身1.2秒，起身后躯干摇晃18度。

个人比较
平时起身时长约3.5秒，平时躯干摆动约5度。

当前判断
两项独立风险证据在4秒内连续出现，当前为橙色风险。

系统处置
已播放一次熟悉语音：“先坐稳再走。”

当前结果
老人已恢复稳定，正在进行60秒观察。

家属建议
当前无需紧急处理，可在早晨主动联系。
```

这会让你们的“个人基线”和“规则可解释性”真正体现在产品界面中，而不只是技术文档里。

## 六、把服务反馈纳入个人记忆

文章认为真正有价值的数据不是普通视频，而是带有“时间、场景、反馈和处置结果”的居家时序数据。

这与当前四对象非常契合：

```text
Observation
→ Evidence
→ RiskEvent
→ InterventionResult
```

你们下一步可以重点保存：

- 本次提醒是否成功送达；
- 老人是否坐稳；
- 家属是否完成联系；
- 访客身份是否核验；
- 事件最后是RESOLVED、ESCALATED还是FALSE_ALARM；
- 哪条规则产生了误报；
- 什么语音最容易让老人配合。

不过要注意：

> 处置结果可以用于后续规则校准，但不能直接把一次危险后的异常值更新成“正常基线”。

你们已经实现的“只有GREEN高质量安全样本才能更新基线”正好可以作为对此问题的技术回答。

## 七、借鉴文章的产品评价指标

文章给出的评价方向比单纯准确率更完整。你们后续实验可以增加以下指标：

| 指标 | 项目中的计算方式 |
|---|---|
| 风险发现提前量 | 从系统触发到模拟跌倒危险点之间的时间 |
| 无效报警比例 | 正常干扰场景中错误进入ORANGE的比例 |
| 每人每天无效打扰次数 | 黄色、橙色提醒中不必要提醒的次数 |
| 干预送达成功率 | Tool调用SUCCESS次数÷总调用次数 |
| 老人动作完成率 | 听到提示后完成坐稳等动作的比例 |
| 风险回落时间 | ORANGE触发到RESOLVED的时间 |
| 事件闭环率 | 有完整InterventionResult的RiskEvent比例 |
| 家属核验完成率 | 诈骗核验卡得到家属反馈的比例 |
| 证据可追溯率 | RiskEvent能够追溯到Evidence、Observation和授权素材的比例 |
| 老人接受度 | 志愿者对提醒音量、内容、打扰程度的评分 |

答辩时不要只说“准确率达到多少”，而要说：

> 我们不仅验证系统能不能发现风险，还验证它是否少打扰、能否完成干预、能否确认恢复，以及家属能否理解和接手。

## 八、隐私部分可以直接吸收文章的四条边界

文章提出的四个原则与你们非常一致：

1. 数据最小化；
2. 观察和诊断分开；
3. 分级授权；
4. 保留人工责任。

可以转化成你们的项目原则：

- 默认不长期保存连续原始视频；
- 心理场景只描述行为趋势，不输出疾病诊断；
- 家属只能看到完成关怀和核验所需的信息；
- 物业或社区必须经过授权，不能查看完整家庭监控；
- 大模型不能修改风险等级；
- RED由人工承接，不自动拨打120；
- 老人和家属可以对系统判断进行纠正；
- 所有模拟数据必须标记 `simulated=true`。

建议前端增加两个很小但有说服力的展示项：

- “数据来源：Mock/回放/公开数据/实机”；
- “授权范围与保存期限”。

你们已经做了输入来源标记，可以继续把它作为项目可信度亮点。

## 九、不建议照搬的内容

这篇文章属于产品与产业观点文章，不是算法论文。因此：

- 不能用它证明30秒、15秒、60秒阈值合理；
- 不能用它证明个人基线算法准确；
- 不能用它替代研究生建议或验证实验；
- 不要声称你们实现了具身机器人；
- 不要增加机器人导航、抓取、移动询问等能力；
- 不要为了模仿文章临时开发物业端、社区端；
- 不要把“情感世界模型”包装成已经训练完成的模型；
- 不要因为文章强调商业服务，就改变7月31日前的跌倒Mock闭环目标。

文章适合支撑“为什么这么设计”，不能支撑“技术效果已经被证明”。

## 十、最建议你们实际修改的三处

在不影响7月31日开发的前提下，优先修改：

1. 在PPT中加入“家庭状态入口”定位

> 从识别单一事件，升级为理解个人生活变化并完成责任闭环。

2. 把心理故事改成“多项生活语义＋主动确认”

不要只讲活动量下降，要加入作息、活动范围、互动节奏和家属反馈。

3. 增加责任与反馈闭环

```text
谁发现
→ 为什么提醒
→ 通知谁
→ 谁确认
→ 谁处置
→ 结果如何返回系统
```

对你们而言，这篇文章最大的价值可以概括为一句话：

> 它证明了“萤目守望”真正应该竞争的不是多识别几个风险类别，而是谁能更准确地理解老人相对自身习惯的变化，并把变化转化为一次低打扰、可解释、有人负责、能够回落的服务闭环。
