# 8月14日后常易铭语音与行为模块联调交付

## 1. 交付结论

本次完成的是“语言与行为轨迹算法适配器 + 后端输入材料”，输出遵循 Freeze v1.0：

- 只输出 `Observation` 和 `Evidence`，不输出 `GREEN/YELLOW/ORANGE/RED`；
- `fraud_keyword` 只表示高风险交互特征，不表示系统识别出诈骗；
- 单段视频只生成当前片段行为 Observation，不凭空生成长期趋势 Evidence；
- 预设动作视频固定为 `source_mode=RECORDED_REPLAY`、`simulated=true`；
- 音频质量不足明确输出 `SYSTEM/audio_quality_low`，不强行分类。

## 3. 已完成的接口输入规则

### 3.1 行为模块

OpenCV 先分析未绘制原始帧，再由 `behavior_observations.py` 生成 Observation，避免框、文字和轨迹污染运动区域。输出特征包括：

- `max_person_count`
- `person_detected_frame_ratio`
- `dominant_activity_level`
- `max_motion_area`
- `track_point_count`
- `travel_distance`（像素，不是米）
- 启用区域配置后增加访问区域、转换次数、最长停留和区域顺序

检测比例同时作为 `data_quality`；HOG 漏检时会降低置信度和数据质量，并在 `metadata.detection_status` 标记 `LOW_DETECTION`。不会把漏检直接解释为跌倒。

### 3.2 语音模块

`audio_evidence.py` 先归一化空格和全角字符，再匹配“保证收益、验证码、马上转账”等交互特征组：

- 多个特征组命中：生成 `FRAUD/fraud_keyword`；
- 只有一个特征组命中：证据严重度和置信度封顶，不能独立升级风险；
- 质量分数低于 `0.45`：生成 `SYSTEM/audio_quality_low`，关键词仍只能作为低质量参考；
- 不命中关键词：保留转写和关键词计数 Observation，不生成诈骗 Evidence。

质量指标只接受脱敏比例字段：`data_quality`、`non_silent_ratio`、`clipping_ratio`、`transcript_completeness`。

### 3.3 多日趋势

输入为每天的访问区域数、房间转换数、白天/夜间活动分钟数和当日数据质量。前面的日期形成个人基线，最后一天作为当前值：

- 少于 3 个历史日：`INSUFFICIENT`，只输出 Observation；
- 3 至 6 个历史日：`PROVISIONAL`，只输出 Observation；
- 不少于 7 个历史日：`STABLE`，才允许输出 `activity_range_decline`、`room_transition_decline`、`day_night_rhythm_change`。

当前趋势文件是 `MOCK`，仅用于接口联调，不能当作真实长期监测结论。
趋势与单段行为摘要的 `source_mode`/`simulated` 不一致时，适配器会拒绝合并，必须分开提交以保留数据来源。

## 5. 后端对接顺序

若后端按单对象接口入库，顺序固定为：

1. `POST /api/v1/assets`，提交 `samples/asset-c6c-golden.example.json`；
2. 对 Bundle 的每条 Observation 调用 `POST /api/v1/observations`；
3. 对 Bundle 的每条 Evidence 调用 `POST /api/v1/evidence`。

回放输入建议把 Asset 的 `captured_at` 传给 `generate_behavior_bundle.py --timestamp`，避免把算法处理时间误当成采集时间。

本模块的 `src/submit_to_backend.py` 会先做本地字段、关联 ID、来源和模拟标识校验，再按 Observation → Evidence 顺序提交。它不保存后端返回的最终风险等级。

仅本地校验命令：

```powershell
python .\src\submit_to_backend.py `
  --bundle .\samples\behavior_bundle.c6c-replay.example.json `
  --base-url http://127.0.0.1:8000 `
  --log-output .\output\behavior_dry_run.json `
  --dry-run
```

## 6. 仍需后端确认的问题

这些不是我可以单方面决定的接口细节，请后端在联调前确认：

1. 算法 Worker 是接收完整 Bundle，还是接收 `asset_id` 后分别读取 Observation/Evidence；
2. `Asset.available=false` 且 `fallback_kind=LOCAL_AUTHORIZED_FILE` 时，后端是否允许先入库元数据，再由本机 Worker 读取授权文件；
3. Observation 的 `timestamp` 应使用算法处理时间，还是必须继承 Asset 的 `captured_at`；
4. 后端是否需要稳定的 `run_id`/幂等键，以避免同一回放重复生成随机 Observation ID；
5. 长期趋势的日汇总由哪个 Worker/接口提供，字段是否与 `samples/mock_daily_activity.json` 一致；
6. 原始转写文本是否允许落库；若不允许，需要后端确认只保存关键词标签和脱敏片段的字段；
7. 单段行为结果是否接受 `evidence=[]`，还是由后端补充 `tracking_lost` 等系统质量证据；
8. 真实 Webhook、实时抓拍、语音喊话和临时播放地址仍按萤石阶段文档标记为未完全验证，不应被本模块声明为已实现。
