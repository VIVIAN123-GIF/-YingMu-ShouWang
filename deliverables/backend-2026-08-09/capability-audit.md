# 后端能力核对（冻结方案）

本核对只记录已验证能力与明确缺口，不将回放或 Mock 结果表述为实时实机结果。

| 冻结能力 | 当前状态 | 验证或边界 |
|---|---|---|
| 四对象与 Asset 统一入库 | 已完成 | Asset、Observation、Evidence、RiskEvent、InterventionResult 均有接口与数据库模型。 |
| 素材到证据的追溯 | 已完成 | Evidence 经 Observation 的 `asset_id` 追溯至 Asset。 |
| C6c 录制回放实际入库 | 已验证 | 最新行为包的 Asset 和 6 条 Observation 已实际写入临时 SQLite，并验证重复 Observation 幂等。 |
| 跌倒状态机 | 已验证（Mock） | 可完成 ORANGE、干预、观察与回落；真实 C6c 行为包没有 Evidence，未用于伪造闭环。 |
| 心理 Evidence 接收 | 已具备 | 冻结类型可校验、保存、查询；心理趋势到 YELLOW、反馈和回落的完整规则执行仍待接入/确认。 |
| 诈骗 Evidence 接收 | 已具备 | 冻结类型可校验、保存、查询；多证据到事件、身份核验和回落的完整规则执行仍待接入/确认。 |
| 家属反馈接口 | 已具备 | `POST /api/v1/events/{event_id}/feedback` 已提供。 |
| 萤石告警接收 | 已临时验证 | `ys.iot` Webhook 可写入告警表；正式固定 HTTPS 与官方签名规则尚未完成验收。 |
| 自动告警触发算法 | 未实现 | 当前 Webhook 不会直接调用算法服务，不能宣称自动设备闭环。 |
| 正式设备语音/消息干预 | 待核验 | 可保留真实失败和 Mock 降级记录，尚无正式成功验收结论。 |
| 凭证与隐私控制 | 已具备基础措施 | `.env.example` 默认关闭临时未签名模式；真实凭证不进入仓库，验收摘要脱敏。 |

## 当前可作出的结论

1. 后端可以实际接收真实 C6c 录制素材的算法结果；
2. 当前行为结果包不含 Evidence，因此只能证明“素材与 Observation 接入”，不能证明风险事件或恢复闭环；
3. 风险闭环、正式萤石能力与设备到算法自动链路必须分别验收，不能互相替代。
