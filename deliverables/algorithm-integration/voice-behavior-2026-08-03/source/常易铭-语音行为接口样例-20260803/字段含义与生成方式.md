# Freeze v1.0 字段含义与生成方式

## 1. Observation字段

| 字段 | 类型 | 含义 |
|---|---|---|
| `schema_version` | 字符串 | 固定为`1.0`。 |
| `observation_id` | 字符串 | 单条直接观测的全局唯一ID；相同ID和相同内容用于幂等重试。 |
| `resident_id` | 字符串 | 脱敏居民标识；Evidence必须与其引用的Observation一致。 |
| `timestamp` | ISO 8601时间 | 观测时间，必须含时区，例如`+08:00`。 |
| `source` | 字符串 | 产生特征的适配器或数据来源，例如`audio`、`behavior_statistics`。 |
| `feature_name` | 字符串 | 特征名称，例如`audio_transcript`、`current_visited_region_count`。 |
| `feature_value` | 数字/字符串/布尔 | 直接观测值，不可使用对象或数组。 |
| `unit` | 字符串或`null` | 单位，例如`count`；无单位必须显式写`null`。 |
| `location` | 字符串或`null` | 脱敏区域，例如`living_room`。 |
| `confidence` | 0到1浮点数 | 当前算法对该观测的置信程度。样例值仅用于联调。 |
| `data_quality` | 0到1浮点数 | 输入质量或可用程度。低质量时后端可执行质量门控。 |
| `source_mode` | 枚举 | `LIVE_DEVICE`、`RECORDED_REPLAY`、`PUBLIC_DATASET`或`MOCK`。 |
| `asset_id` | 字符串或`null` | 经授权素材的脱敏ID；不得写本机路径或设备凭据。 |
| `simulated` | 布尔 | 是否为模拟/合成数据。 |
| `metadata` | 对象 | 可选适配器信息；核心业务字段不能塞入这里替代冻结字段。 |

## 2. Evidence字段

| 字段 | 类型 | 含义 |
|---|---|---|
| `schema_version` | 字符串 | 固定为`1.0`。 |
| `evidence_id` | 字符串 | Evidence全局唯一ID。 |
| `observation_ids` | 字符串数组 | 该Evidence依赖的Observation ID；提交Evidence前这些ID必须已经入库。 |
| `resident_id` | 字符串 | 必须与关联Observation一致。 |
| `timestamp` | ISO 8601时间 | Evidence形成时间，必须含时区。 |
| `risk_domain` | 枚举 | `FALL`、`MENTAL`、`FRAUD`或`SYSTEM`。 |
| `evidence_type` | 字符串枚举 | 本包使用冻结值`fraud_keyword`和`activity_range_decline`。 |
| `severity` | 0到1浮点数 | 该特征的严重程度，不是最终风险等级。 |
| `confidence` | 0到1浮点数 | Evidence判断置信度。 |
| `data_quality` | 0到1浮点数 | Evidence所依据数据的质量。 |
| `baseline_value` | 数字或`null` | 个人基线；无合理基线时使用`null`。 |
| `current_value` | 数字或`null` | 当前统计值。 |
| `baseline_deviation` | 数字或`null` | 本样例统一使用`current_value - baseline_value`；无法比较时为`null`。 |
| `time_scale` | 枚举 | `SHORT`、`MEDIUM`或`LONG`。 |
| `location` | 字符串或`null` | Evidence对应的脱敏区域。 |
| `explanation` | 字符串 | 面向审计的解释，必须说明限制与建议复核方式。 |
| `adapter_version` | 字符串 | 生成Evidence的适配器版本。 |
| `source_mode` | 枚举 | 必须继承其引用Observation的`source_mode`。 |
| `simulated` | 布尔 | 必须继承其引用Observation的`simulated`。 |

## 3. 当前样例的生成逻辑

### 3.1 语音组

输入是合成话术文本的录音回放。Whisper产生转写后，关键词适配器只统计冻结词组命中：

```text
转写文本
  -> audio_transcript Observation
  -> fraud_keyword_match_count Observation
  -> fraud_keyword Evidence
```

样例中命中3类话术，因此`current_value`为`3.0`。`baseline_value`和`baseline_deviation`使用`null`，因为单次关键词命中没有合理个人基线。Evidence使用`FRAUD + SHORT + RECORDED_REPLAY + simulated: true`。

现有Demo的实际Observation生成命令：

```powershell
python .\src\whisper_demo.py .\output\synthetic_test.wav `
  --model tiny `
  --language Chinese `
  --observation-output .\output\audio_observations.json `
  --resident-id resident-interface-001 `
  --asset-id asset-synthetic-audio-20260803-0001 `
  --simulated
```

当前阶段不得因单个关键词直接升级风险；音频质量不足时应输出`audio_quality_low`并降低置信度或停止生成诈骗Evidence。

### 3.2 行为组

行为Demo先由最大HOG人体框中心和人工多边形区域得到访问区域统计，再比较模拟多日个人基线：

```text
中心轨迹 + 人工区域
  -> 当前访问区域数Observation
个人多日统计
  -> 基线访问区域数Observation
二者比较
  -> activity_range_decline Evidence
```

样例中基线为4、当前为2，因此`baseline_deviation = 2 - 4 = -2`。Evidence使用`MENTAL + LONG + MOCK + simulated: true`，只说明活动范围下降，不作心理诊断。

现有Demo的实际区域统计命令：

```powershell
python .\src\behavior_demo.py `
  --input 0 `
  --max-seconds 30 `
  --region-config .\samples\regions.example.json `
  --statistics-output .\output\region_statistics.json `
  --observation-output .\output\region_observations.json
```

实际部署前必须按摄像头画面调整多边形区域，并使用多日数据建立个人基线。HOG漏检时应降低`data_quality`，像素距离不得解释为现实米数。

## 4. 后端约束重点

1. 每个请求体只能是一个对象，不能把Observation数组直接POST到单条接口。
2. 必须先写入Observation，再写入引用它们的Evidence。
3. Evidence与Observation的`resident_id`、`source_mode`、`simulated`必须一致。
4. 所有时间必须含时区，所有分数必须在0到1。
5. 可空字段使用JSON的`null`，不要使用空字符串、`None`或省略必填字段。
6. 同一ID相同内容属于幂等重试；同一ID不同内容应返回409。
