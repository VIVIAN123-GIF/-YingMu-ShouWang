# “萤目守望”接口规范

版本：Schema 1.0 / ruleset-v1.2 + ruleset-v1.3-min兼容稿

## 1 通用约定

API前缀为`/api/v1`，JSON使用UTF-8，时间必须是带时区的ISO 8601。写接口使用稳定对象ID实现幂等；HTTP 201表示首次创建，HTTP 200表示幂等复用。响应携带`X-Request-ID`用于审计。

## 2 核心对象约束

Observation必须包含来源、特征、值、置信度、数据质量、来源模式和模拟标识。Evidence必须引用至少一个Observation，携带风险域、证据类型、严重度、质量、时间尺度和适配器版本。RiskEvent由后端生成，前端和算法不得提交最终风险等级。

## 3 主要接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/health` | 版本与健康检查 |
| POST | `/api/v1/observations` | 幂等写入Observation |
| POST | `/api/v1/evidence` | 写入Evidence并触发风险评估 |
| GET | `/api/v1/events` | 查询统一事件时间轴 |
| GET | `/api/v1/events/{id}` | 查询证据、观测、干预和RuleTrace |
| POST | `/api/v1/events/{id}/intervene` | 执行已批准干预策略 |
| POST | `/api/v1/events/{id}/results` | 写入老人回应或工具结果 |
| POST | `/api/v1/events/{id}/feedback` | 写入家属关怀或身份核验 |
| GET | `/api/v1/events/{id}/explanation` | 查询持久化解释，不重复调用模型 |
| GET | `/api/v1/residents/{id}/forewarning/latest` | 查询最新工程预警快照；缺数据返回null，不伪造GREEN |
| GET | `/api/v1/residents/{id}/forewarning` | 按时间范围查询预警快照 |
| GET | `/api/v1/events/{id}/forewarning` | 查询事件干预前后快照 |
| GET | `/api/v1/scene-calibrations/{id}` | 只读查询已安装的脱敏场景配置 |
| GET | `/api/v1/device/status` | 查询脱敏设备状态 |
| GET | `/api/v1/alarms/processing` | 查询告警处理任务 |

## 4 算法适配边界

统一接口为`run(AlgorithmJob) -> AdapterBatch`。算法只输出Observation、Evidence和失败状态；后端负责超时、有限重试、熔断、幂等和风险状态。媒体定位符仅在私有进程边界使用，不进入公开验收响应。

`RiskEvaluateResponse.forewarning_snapshot`为可选兼容字段。ForewarningSnapshot中的数值统一称为工程风险指数，不是跌倒概率；观察等级不替代RiskEvent裁决。场景配置只能使用本地校验安装工具写入私有配置目录，不提供公开写接口。

## 5 错误和安全

业务错误返回结构化错误码、消息和request_id。Token、AppSecret、验证码、完整设备序列号、临时URL、storage_key和原始语言转写不得出现在公开响应、RuleTrace或大模型请求中。控制型解释入队接口需要`X-Control-Token`，浏览器不持有该令牌。
