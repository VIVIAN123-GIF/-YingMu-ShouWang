# “萤目守望”部署与运行说明

适用版本：工程可行性验证阶段Windows发布说明

## 1 最快启动

解压`萤目守望-Windows.zip`后，双击`start-demo.cmd`。程序会创建独立演示数据库，启动API和两个Worker，写入明确标记为Mock的固定闭环，并打开浏览器。评审应看到首页风险总览、统一事件时间轴、事件证据与干预状态，以及醒目的来源/模拟标识；这些固定数据用于离线演示，不代表实时萤石告警。

停止程序：回到启动窗口按`Ctrl+C`。程序应关闭全部子进程；日志保存在`runtime/logs/`。

## 2 命令行入口

```powershell
YingMuShouWang.exe demo
YingMuShouWang.exe live
YingMuShouWang.exe server
YingMuShouWang.exe alarm-worker
YingMuShouWang.exe agent-worker
```

`demo`用于离线评审演示；`live`用于授权实机环境；后三个命令用于诊断。默认地址为`http://127.0.0.1:8000`，健康检查为`/health`。

## 3 真实设备配置

从`config/.env.example`创建`config/.env.local`，只在本机填写AppKey、AppSecret、设备序列号、Webhook密钥和授权记录。禁止提交或发送该文件。

真实模式至少要求：

```text
EZVIZ_APP_KEY
EZVIZ_APP_SECRET
EZVIZ_DEVICE_SERIAL
```

真实模式拒绝`EZVIZ_WEBHOOK_ALLOW_UNSIGNED_TEST=true`。当前已验证设备状态、Webhook、抓拍、H.264媒体获取和媒体进入算法调度。2026年9月2日，团队在另一台实际部署计算机上完成真实设备采集、系统分析、风险分级、干预记录、后续观察和风险回落的工程闭环联调。该完成状态依据团队现场操作和复核确认，不在本说明中补写当前工作区未归档的事件编号、定量性能或文件哈希。萤石服务端语音只有在真实日志验证后才能设置`EZVIZ_VOICE_VERIFIED=true`，否则界面使用明确标记的Mock或本地文字提醒。

`.env.local`不得进入源代码包、截图、日志或演示视频。评审材料只展示脱敏设备信息、HTTP/业务状态、耗时和结果，不展示AppSecret、AccessToken、验证码、完整设备序列号或临时播放地址。

## 6 构建Windows发布包

在仓库根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build_windows_release.ps1
```

脚本执行前端测试和生产构建，安装固定版PyInstaller，生成onedir程序，启动完整Demo栈并写入固定Mock闭环，验证首页后正常退出，计算SHA-256清单并压缩为`output/windows/萤目守望-Windows.zip`。当前目录中的既有ZIP早于最新代码和材料修订；正式提交哈希须在最终重建后从新清单填写，不沿用旧包哈希。

## 7 验收检查

- 在未安装Python和Node的Windows电脑上解压并启动；
- 3分钟内打开首页，九个一级入口可访问；
- 演示页面显示Mock或回放标签；
- 关闭后没有残留Worker；
- 发布包敏感扫描无发现；
- `MANIFEST-SHA256.txt`覆盖包内文件。

2026年9月2日，另一台实际部署计算机上的真实设备部署和工程闭环已由团队现场确认完成。文档修订后的最终Windows提交包仍须重新构建，并复核其自身的启动、退出、敏感扫描和清单；该发布收口不改变异机部署已经完成的事实。

验收时应同时确认：Demo页面保持`MOCK`标识；授权录像演示保持`RECORDED_REPLAY/simulated=true`；真实平台页面只展示实际验证到的能力，任何降级状态均明确可见。

## 8 故障定位

启动失败时先查看`runtime/logs/demo.log`和三个进程日志。端口占用时使用`demo --port 8010`。模型缺失、配置缺项或真实模式启用无签名Webhook时，启动器会明确退出，不会自动降级为真实成功。
