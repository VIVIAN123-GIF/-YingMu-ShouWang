# 《荧目守望》初审演示视频脚本（青年志愿者版）

## 使用说明

- 成片时长：6–7 分钟；主摄像机连续录制，不跳剪、不插入 PPT。
- 青年志愿者仅执行安全、受控的模拟动作，不冒充老年人，不作临床效果宣称。
- 画面持续显示来源标签：`LIVE_DEVICE`、`RECORDED_REPLAY`、`MOCK`、`EXPERIMENT_RESULT`；纯界面/部署页可使用 `SOFTWARE`。
- 真实设备和运行结果必须现场展示；趋势、心理和诈骗扩展场景必须明确标注模拟来源。

## 连续拍摄脚本

| 时间 | 画面与操作 | 现场台词/字幕 |
|---|---|---|
| 0:00–0:25 | 客厅全景：C6c、桌椅、行走区、电脑；志愿者只露侧身或背影。 | “本次演示使用已授权的青年志愿者完成受控模拟动作，不涉及真实老年人影像，也不构成医疗诊断。” |
| 0:25–1:00 | 镜头靠近设备，展示安装高度、视野和 `C6c-pos01`；转向电脑打开设备状态、Webhook 或抓拍记录。 | “设备固定部署在客厅入口，覆盖起身、行走和转身区域。当前设备在线，数据通过统一适配器进入系统。” |
| 1:00–2:30 | 高风险模拟：志愿者坐稳，快速但可控起身，双脚支撑，轻微受控躯干摇摆，随后坐回并保持稳定；安全员站在侧后方。电脑依次展示 `Observation`、`Evidence`、`RiskEvent`、等级和干预状态。 | “现在执行 `POS_RAPID_RISE_SWAY`。动作只模拟风险信号，不实施摔倒或危险失衡。” “系统结合多项证据计算风险，当前进入橙色并创建事件。” |
|  | 点击干预工具；语音未完成真实验证时展示 `MOCK`、`simulated=true`，使用本地文字提醒。等待观察窗口，展示 `INTERVENING` → `OBSERVING` → `RESOLVED`。 | “干预结果只记录工具执行，不直接代表风险解除。连续观察满足规则且没有新证据后，事件才回落为已解决。” |
| 2:30–3:20 | 第二名志愿者正常起身、行走、缓慢转身并稳定站立。系统并排打开高风险与低风险事件。 | “这是低风险对照样本：动作和证据均在个人基线范围内。” “系统比较的是证据组合和趋势，不是单个动作。” |

| 4:05–4:45 | 两名青年志愿者扮演访客和家庭成员，仅使用虚构身份、金额和验证码；展示未授权访客、异常停留、高风险话术组合，随后点击身份核验。 | “诈骗场景需要多证据组合。系统不会仅凭一个关键词认定诈骗，最终处置需要家属或授权人员核验。” |
| 4:45–5:35 | 打开实验结果页面或终端，展示实际 JSON/报告读数：P03 固定评测 24 个片段、规则覆盖与一致性 24/24、有效起身转换 11/12。指向事件 ID、规则版本、Evidence ID、干预结果和回落状态。 | “这里展示的是项目工程验证记录，不将小样本结果包装成老年人群体准确率。每个输出都能追溯到片段、规则版本和事件日志。” |
| 5:35–6:10 | 展示脱敏授权编号、参与者 ID、私有媒体目录、Windows 一键启动和离线降级页面。 | “原始媒体只保存在授权私有目录。外部服务不可用时，系统保留事件状态和失败日志，并明确降级。” |
| 6:10–6:40 | 镜头回到客厅全景和系统首页，风险状态恢复绿色。 | “荧目守望的闭环是：连续采集、个体基线、多源证据、分级干预和回落确认。” |

## 拍摄口令

记录员每段开始前口述：`clip_id`、参与者编号、场景名、来源模式。统一口令为“准备拍摄”“开始动作”“动作结束，保持”“拍摄结束”。任何不适立即喊“停止”，该段标记为 `ABORTED`，不得硬拍。

## 输出与隐私要求

- 1920×1080、25/30fps、H.264 MP4；主摄像机与屏幕录制保持同一时间轴。
- 不展示姓名、电话、账号、Token、门牌、支付页面或绝对路径。
- 志愿者和画面中任何真人均须有书面授权；优先使用背影、侧影或打码。
- 不把 `MOCK`、`RECORDED_REPLAY` 说成实时识别，不展示未经实际结果支持的准确率、召回率或临床结论。
