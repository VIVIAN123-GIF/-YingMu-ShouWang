# v1.5正式性能验证拍摄脚本

版本：1.0  
适用范围：同一健康成年参与者、同一设备、同一机位、受控工程验证  
拍摄规模：28组主录像，确定性导出64个正式输入资产  

## 1. 先说明“满足要求”的边界

严格执行本脚本，可以保证素材数量、动作完整性、质量对照、双活动窗口趋势条件、预声明标签和盲测流程满足正式补充验证要求。它不能保证算法一定达到预期性能；未检出、误报和质量门控失败都必须原样进入正式统计。

当前`ruleset-v1.5`和适配器仍带有`EXPLORATORY_REANALYSIS`声明。正式拍摄开始前，技术负责人必须先完成一次版本冻结：固定规则、阈值、模型、适配器、个人基线快照、执行器和评价规范的SHA-256，并为该不可变组合分配`FORMAL_RULESET_ID`。未填写冻结编号和哈希时，不得开始正式拍摄。

本轮只能声明：固定参与者、固定设备和固定机位下的受控工程性能；不能声明临床准确率、老人群体性能或跨人泛化。

## 2. 为什么是28组主录像、64个输入资产

- 24组识别主录像：6类场景，每类4组。
- 4组质量降级主录像：4类门控各1组。
- `POS_RAPID_RISE_SWAY`每组只需要一个即时风险资产，共4个资产。
- 慢速小步、不对称和近阈值正常共12组，每组导出T1/T2两个`WALK`资产，共24个资产。
- 正常起身行走和快速起身稳定共8组，每组导出I1/I2两个即时风险全窗口，以及T1/T2两个纯行走窗口，共32个资产。
- 质量降级录像每组一个资产，共4个资产。
- 正式推理总输入为`4 + 24 + 32 + 4 = 64`个资产；正式统计仍以28个`sequence_id`为实验单位，不能把派生窗口虚增成独立样本。

T1与T2必须间隔小于180秒。T1用于建立本次序列的第一次活动观察，T2用于检验趋势持久化；不得复制同一文件、复用同一哈希或把同一动作重复提交两次。

当前D1-D3冻结基线只有`WALK`上下文，`POST_RISE_LOCOMOTION`、`RISE_ONLY`和`STATIC_OR_UNKNOWN`均不可用。正常起身行走和快速起身稳定因此必须同时导出：包含起身过程的I1/I2用于即时风险负样本，排除起身过程的T1/T2用于与`WALK`个人基线公平比较。不得用缺少匹配基线的降级结果冒充趋势真阴性。

## 4. 人员与安全

- 参与者：与D1-D3相同的已授权健康成年人；不饮酒、不在头晕、疼痛、疲劳明显时拍摄。
- 安全员：始终站在画面外侧后方，伸手可及，但不得遮挡人体或拉拽参与者。
- 口令员：只读固定口令，不查看任何算法输出。
- 数据管理员：负责文件名、时间、哈希、授权和状态登记，不参与阈值调整。
- 推理操作员：标签与数据锁定后才接收素材；拍摄人员在正式结果冻结前不接触输出。

禁止真实跌倒、闭眼行走、绊脚、跳跃、交叉腿、突然冲刺和危险失衡。任何人说“停止”立即终止，该次标记`ABORTED`，不得为了凑数量继续动作。

## 5. 机位、画面和环境

1. 使用与D1-D3完全相同的参与者、设备、机位、焦距、分辨率、方向和来源模式；机位变化会使现有个人基线失效。
2. 摄像机、椅子、左右起终点和中央动作区均用地贴固定，拍摄期间不得移动。
3. 推荐1920x1080、25或30fps、H.264 MP4；关闭云台跟踪、自动巡航、数字变焦和美颜。
4. 参与者位于中央时，人体高度占画面高度55%至75%；头顶和鞋底至少各留5%画面余量。
5. 正常质量场景中，头、肩、髋、膝、踝和双脚必须全程可见；只有一名参与者入镜。
6. 行走路线横跨画面，长度3.5至5米；评分窗口内不转身，转身和复位只能发生在第一、第二活动段之间的非评分区间。
7. 穿贴身、与背景有明显对比的上衣和长裤；左右鞋可使用不同颜色鞋带帮助人工复核，但不得粘贴会遮挡关节的物品。
8. 地面防滑、无杂物。除专门的遮挡质量场景外，椅子和家具不得挡住髋、膝、踝。
9. 正常质量录像先录10秒空载预览，由人工确认构图；不得运行v1.5姿态、Evidence或风险推理。

## 6. 统一口令与主录像结构

每组开始前口述：

```text
实验 supplemental-validation-v1.5-formal-r1。
序列编号【sequence_id】；场景【scenario_id】；参与者SV01；标签已预声明。
准备拍摄。任何不适立即说停止。
```

### 6.1 单窗口结构：只用于快速起身后摇晃

主录像时长约30秒：

| 时间 | 动作 |
|---|---|
| 0-5秒 | 坐稳，全身入镜，双脚自然落地。 |
| 5秒 | 口令“开始动作”。 |
| 5-6.5秒 | 在1.0-1.5秒内安全、连续地完成坐到站。 |
| 6.5-12.5秒 | 完成4次清楚的左右躯干换向，同时完成2次可控侧向补偿步；每次侧步约半个肩宽，双脚不交叉。 |
| 12.5-20秒 | 双脚平行、稳定站立，不再摇晃。 |
| 20-25秒 | 口令“动作结束，保持”，继续站稳。 |
| 25-30秒 | 口令“拍摄结束”。 |

人工动作合格线：坐站转换完整；起身后5秒窗口内至少3次清楚换向；至少1只脚出现清楚的离地、侧移、落地过程；头和双脚始终在画面内；不得扶椅、扶墙或真实失衡。

### 6.2 双活动段结构：用于其余20组识别录像

每组拍一条约75秒的主录像。慢速小步、不对称和近阈值正常预声明：

- T1：主录像`00:03.000-00:28.000`，`asset_id=<sequence_id>-T1`。
- T2：主录像`00:42.000-01:07.000`，`asset_id=<sequence_id>-T2`。
- 28-42秒只用于安全复位，不进入任何正式资产和指标。
- T1、T2分别导出、分别计算SHA-256；manifest记录父文件SHA-256、精确起止时间和派生方式。
- 两个资产的`captured_at`按真实窗口起始时间填写，必须相差小于180秒。

正常起身行走和快速起身稳定预声明四个资产：

- I1：主录像`00:03.000-00:28.000`，包含第一次起身和行走，用于即时风险。
- I2：主录像`00:42.000-01:07.000`，包含第二次起身和行走，用于即时风险。
- T1：主录像`00:10.500-00:22.000`，只包含第一次起身完成后的连续行走和稳定结尾，用于趋势。
- T2：主录像`00:49.500-01:01.000`，只包含第二次起身完成后的连续行走和稳定结尾，用于趋势。
- T1/T2内不得残留坐站转换；人工复核必须确认两者均被定义为`WALK`活动窗口。

每个窗口内统一节奏：

| 窗口内时间 | 动作 |
|---|---|
| 0-4秒 | 起始姿态保持稳定，全身入镜。 |
| 4秒 | 口令“开始本窗口动作”。 |
| 4-16秒 | 执行该场景指定动作；行走类至少持续8秒并完成6个完整左右步态周期。 |
| 16-21秒 | 停在终点，稳定站立。 |
| 21-25秒 | 保持全身入镜，不挥手、不下蹲。 |

第一活动段结束后，口令员说“复位，不计入评分”；参与者安全返回起点。第二活动段必须重复同类动作，但不能复制第一段视频。

## 7. 六类识别场景详细动作

### 7.1 POS_RAPID_RISE_SWAY：4组

目标：`IMMEDIATE_ORANGE`。只使用第6.1节单窗口结构。

- 01：起身后先向左倾，再右、左、右；第2次和第4次换向各做一次小侧步。
- 02：起身后先向右倾，再左、右、左；第1次和第3次换向各做一次小侧步。
- 03：起身后左右换向4次；先左脚侧步，再右脚回收，不交叉脚。
- 04：起身后左右换向4至5次；先右脚侧步，再左脚回收，不交叉脚。

动作必须同时具备“躯干往复换向”和“可见补偿步”两个独立现象。仅原地晃肩、仅单侧倾斜、仅快速起身或脚始终不离地，均标记`REJECTED`。

### 7.2 POS_SLOW_SMALL_STEP_SWAY：4组

目标：T1为第一次趋势候选，T2验证持久趋势；预期`YELLOW_NO_ORANGE`。使用双活动段结构。

- 每个窗口从站立开始，以个人正常步速约45%-55%的节奏横向通过画面。
- 连续完成12至16小步，即至少6个完整双侧周期；每步约正常步长的30%-45%。
- 行走时做轻微、连续的左右重心摆动，但不做突然侧步，不模拟跌倒。
- 01/03从画面左向右；02/04从画面右向左。
- T1和T2保持相同方向、相同节奏等级和相同`WALK`活动上下文。

少于6个完整周期、有效行走不足8秒、转身发生在评分窗口、某只脚长期被遮挡，均标记`REJECTED`。

### 7.3 POS_ASYMMETRIC_STEP：4组

目标：专项`gait_instability`，T2同时提供第二活动窗口；预期`YELLOW_NO_ORANGE`。使用双活动段结构。

- 采用安全的“长步-短步”交替，不跛行、不拖脚、不单脚跳。
- 指定长步约为个人正常步长的100%-120%，指定短步约为正常步长的35%-45%；左右步幅差必须肉眼持续可见。
- 每个窗口连续完成至少6个完整双侧周期，评分窗口内不转身。
- 01：左长右短，左向右；02：右长左短，右向左；03：左长右短，右向左；04：右长左短，左向右。
- T1和T2的长短脚设定必须一致。

只出现1至2个不对称步、只是身体侧倾而步幅相同、走到一半恢复正常，均标记`REJECTED`。

### 7.4 NEG_NORMAL_RISE_WALK：4组

目标：I1/I2均`NO_ORANGE`，T2无持久趋势告警。使用双活动段结构并按第6.2节导出四个资产。

- 每个窗口0-4秒坐稳；4-6.5秒以自然速度起身，不刻意快或慢。
- 起身后自然站稳1秒，再以个人正常步速完成6至8个完整双侧周期。
- 步幅对称、躯干自然、无补偿侧步、无持续摇晃。
- 01/03左向右；02/04右向左。两次活动动作等级一致。

### 7.5 NEG_FAST_RISE_STABLE：4组

目标：允许I1/I2出现快速起身观察，但必须`NO_ORANGE`，且T2无持久趋势告警。使用双活动段结构并按第6.2节导出四个资产。

- 每个窗口0-4秒坐稳；4-5.5秒内安全完成快速起身。
- 起身后原地稳定2秒，脚不移动、躯干不做往复摆动。
- 随后按个人正常步速、对称步幅完成6个完整双侧周期。
- 01/03左向右；02/04右向左。

如果参与者起身后因惯性真实跨步或连续摇晃，该段不再属于负样本，标记`REJECTED`，不得事后改成正样本。

### 7.6 NEG_NEAR_THRESHOLD_NORMAL：4组

目标：困难负样本，必须`NO_ORANGE`且T2无持久趋势告警。使用双活动段结构。

- 从站立开始，以个人日常正常范围内偏慢的速度行走，目标节奏为正常步频的80%-90%。
- 步长保持正常步长的80%-100%，左右步幅对称。
- 每个窗口完成6至8个完整双侧周期；允许自然的轻微重心摆动，但不做刻意左右往复、不做补偿步。
- 01/03左向右；02/04右向左。

“接近阈值”由拍摄前的动作定义决定，不能查看正式算法输出后调整速度。明显故意慢走、长短脚或持续摇晃均标记`REJECTED`。

## 8. 四类质量降级场景

质量录像各约20秒，只验证质量门控，统一预期：

```text
target=QUALITY_GATE
expected_assessment=PARTIAL_OR_INSUFFICIENT
expected_state=NO_ORANGE
```

### QG01 家具遮挡

- 0-4秒：参与者全身可见，正常站立。
- 4-7秒：走向固定的实心遮挡物。
- 7-11秒：肩、髋、膝中的大部分被遮挡，核心身体连续不可可靠观察至少2.5秒；参与者在遮挡后继续缓慢移动。
- 11-16秒：重新完整出现并站稳。
- 遮挡物不能覆盖整个镜头，也不能只是挡住一只脚。人工验收必须能确认核心人体连续遮挡至少2秒。

### QG02 双脚离开画面

- 0-3秒：参与者全身可见。
- 3-6秒：向预先标记的近端区域移动。
- 6-16秒：上半身和髋部仍清楚可见，但双踝和鞋底连续位于画面下边界之外至少8秒。
- 16-20秒：保持，不需要恢复全身。
- 不能通过后期裁切制造，必须是原始机位中的真实出画。

### QG03 严重低照度

- 摄像机位置、参与者位置和构图与正常场景一致。
- 禁用会自动把画面变亮的红外夜视或补光模式，避免算法实际看到明亮灰度图。
- 0-15秒：参与者缓慢站立并做两次轻微转身，全身尽量可见。
- 拍摄前只允许使用不包含姿态/风险推理的原始像素检查：人物所在固定中央区域灰度中位数目标低于46/255，P10目标低于20/255。
- 不得运行v1.5来试拍或根据其`LOW_ILLUMINATION`结果调整灯光。

### QG04 第二人进入

- 0-4秒：主参与者独自全身入镜。
- 4-7秒：第二名已授权成年人进入画面。
- 7-12秒：两人相距至少1米、身体轮廓不重叠，连续共同入镜至少4秒。
- 12-17秒：第二人离开，主参与者继续站稳。
- 不能只伸手、探头或在背景边缘一闪而过；人工必须能确认两个完整或大部分完整的人体。

## 9. 每组拍完立即进行的人工验收

验收人员只能看原始视频，不得查看姿态特征、Evidence、状态、分数或任何算法输出。

| 检查项 | 正常识别场景 | 质量场景 |
|---|---|---|
| 文件可播放、时长和帧率合格 | 必须 | 必须 |
| 人体完整入镜 | 全程必须 | 除目标缺陷外尽量保持 |
| 只有一人 | 必须 | QG04例外 |
| 双脚可见 | 全程必须 | QG02例外 |
| 光照正常 | 必须 | QG03例外 |
| 两个活动段动作完整 | 双活动段场景必须 | 不适用 |
| 行走至少8秒、6个双侧周期 | 行走场景必须 | 不适用 |
| 场景目标动作肉眼存在 | 必须 | 目标缺陷必须存在 |
| 安全中止 | 不得发生 | 不得发生 |

状态定义：

- `VALID`：预声明动作或质量缺陷完整、清楚、可人工评估，且无安全中止。
- `ABORTED`：参与者或安全员在完成前停止。
- `REJECTED`：完成拍摄但目标动作/缺陷缺失、时长不足、出画、遮挡、多人、低照等不符合该场景要求。

允许在标签锁定、正式推理开始前因客观拍摄缺陷重拍，但必须使用新的`sequence_id/take_id`，保留原文件及拒绝原因。绝不允许因为算法没有给出预期输出而重拍、删片、改标签或换阈值。

## 10. 锁定、导出和一次性推理

1. 28组主录像全部完成并由两名人员复核后，冻结`VALID/ABORTED/REJECTED`状态。
2. 按预声明时间从20组双活动段主录像导出资产；其中12组导出T1/T2，8组起身负样本导出I1/I2/T1/T2。导出参数、父文件哈希、子文件哈希和时间边界写入manifest。
3. 正常做法是无滤镜、无裁切、无变速、无镜像；若转码，全部资产必须使用同一固定命令和编码参数。
4. 生成主录像、正式资产、标签、规则、模型、执行器和评价规范的SHA-256清单并锁定。
5. 由独立人员生成固定随机运行顺序；同一序列的T1必须在T2之前，间隔时间使用真实`captured_at`；I1/I2只进入即时风险端点。
6. 一次性运行全部64个资产。模块失败、超时、低质量、无Evidence都保留，禁止选择性重跑。
7. 指标以`sequence_id`为单位：T1是先导窗口，T2是该序列的正式趋势判定点；派生资产不能当成独立统计样本。
8. 即时ORANGE：4个快速起身摇晃序列为正，其余20个识别序列为负。
9. 趋势：4个慢速小步序列和4个不对称序列为正，12个负样本序列为负；在T2读取持久趋势结果，并分开报告两类目标Evidence。所有趋势资产必须为`WALK`，不得把上下文基线缺失计为真阴性。
10. 质量门控：4个质量序列为正，24个正常质量识别序列为负；一个识别序列只有其全部正式资产均未错误降级才算质量负样本通过。
