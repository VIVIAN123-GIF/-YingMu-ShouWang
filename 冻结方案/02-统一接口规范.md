# 02 统一接口规范

## 一、接口原则

1. 算法模块只输出Evidence，不直接输出最终绿黄橙红等级；
2. 所有时间使用ISO 8601格式并包含时区；
3. 所有分数统一为0到1；
4. 缺失值使用null，不使用0代替；
5. 每条证据必须包含置信度和数据质量；
6. 每个风险事件必须能够追溯到原始证据；
7. 所有接口包含schema_version，当前固定为1.0；
8. 接口字段修改必须由张薇和冷雨彤共同确认；7月31日前字段版本固定为1.0；
9. 设备差异必须隔离在DeviceAdapter内，算法和前端不得直接依赖张薇的萤石个人账号；
10. 每个视频、Observation和Evidence都必须可追溯到输入来源及模拟状态。

## 二、枚举冻结

### 2.1 风险方向

| 值 | 含义 |
|---|---|
| FALL | 跌倒及跌倒前兆 |
| MENTAL | 心理健康趋势 |
| FRAUD | 诈骗及高风险交互 |
| SYSTEM | 设备和数据质量 |

### 2.2 风险等级

| 值 | 含义 |
|---|---|
| GREEN | 正常，更新基线 |
| YELLOW | 持续趋势，低打扰关注 |
| ORANGE | 多证据高风险，需要即时柔性干预 |
| RED | 持续危险或无响应，需要人工接管 |

### 2.3 事件状态

| 值 | 含义 |
|---|---|
| OPEN | 已创建，等待处理 |
| INTERVENING | 正在执行干预 |
| OBSERVING | 干预后观察 |
| RESOLVED | 风险已回落 |
| ESCALATED | 已升级人工接管 |
| FALSE_ALARM | 人工确认误报 |

### 2.4 输入来源

| 值 | 含义 |
|---|---|
| LIVE_DEVICE | 唯一萤石C6c实时或准实时输入 |
| RECORDED_REPLAY | 同一摄像机预录的模拟实验回放 |
| PUBLIC_DATASET | URFD、SisFall等公开数据 |
| MOCK | 人为构造的接口或Evidence数据 |

## 三、Observation观测对象

Observation由感知层生成，记录直接观测结果。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| schema_version | string | 是 | 固定1.0 |
| observation_id | string | 是 | 全局唯一 |
| resident_id | string | 是 | 老人标识 |
| timestamp | datetime | 是 | 含时区 |
| source | string | 是 | pose、tracking、audio、environment、questionnaire等 |
| feature_name | string | 是 | 例如sit_to_stand_duration |
| feature_value | number/string/bool | 是 | 特征值 |
| unit | string/null | 是 | 秒、比例、次数等 |
| location | string/null | 是 | bedroom、living_room、corridor等 |
| confidence | number | 是 | 感知模型置信度 |
| data_quality | number | 是 | 画面或音频质量 |
| source_mode | enum | 是 | LIVE_DEVICE、RECORDED_REPLAY、PUBLIC_DATASET、MOCK |
| asset_id | string/null | 是 | 可追溯的视频、音频或云资源标识，不记录公开访问密钥 |
| simulated | bool | 是 | 是否为模拟实验或构造数据 |
| metadata | object | 否 | 模型版本、摄像机等 |

示例：

    schema_version: "1.0"
    observation_id: "obs-20260731-0001"
    resident_id: "resident-001"
    timestamp: "2026-07-31T03:07:01+08:00"
    source: "pose"
    feature_name: "sit_to_stand_duration"
    feature_value: 1.2
    unit: "second"
    location: "bedroom"
    confidence: 0.92
    data_quality: 0.88
    source_mode: "MOCK"
    asset_id: "asset-fall-0001"
    simulated: true
    metadata:
      model_version: "mediapipe-v1"

## 四、Evidence证据对象

Evidence由任务适配器根据Observation生成，是智能体唯一接受的风险输入。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| schema_version | string | 是 | 固定1.0 |
| evidence_id | string | 是 | 全局唯一 |
| observation_ids | array | 是 | 关联Observation |
| resident_id | string | 是 | 老人标识 |
| timestamp | datetime | 是 | 证据产生时间 |
| risk_domain | enum | 是 | FALL、MENTAL、FRAUD、SYSTEM |
| evidence_type | string | 是 | rapid_rise、activity_decline等 |
| severity | number | 是 | 异常程度 |
| confidence | number | 是 | 证据置信度 |
| data_quality | number | 是 | 数据质量 |
| baseline_value | number/null | 是 | 个人基线 |
| current_value | number/null | 是 | 当前值 |
| baseline_deviation | number/null | 是 | 标准化偏离 |
| time_scale | string | 是 | SHORT、MEDIUM、LONG |
| location | string/null | 是 | 场景区域 |
| explanation | string | 是 | 面向系统的简短解释 |
| adapter_version | string | 是 | 适配器版本 |
| source_mode | enum | 是 | 继承关联Observation的输入来源 |
| simulated | bool | 是 | 是否来自模拟实验或构造数据 |

示例：

    schema_version: "1.0"
    evidence_id: "evi-fall-0001"
    observation_ids:
      - "obs-20260731-0001"
    resident_id: "resident-001"
    timestamp: "2026-07-31T03:07:02+08:00"
    risk_domain: "FALL"
    evidence_type: "rapid_rise"
    severity: 0.78
    confidence: 0.92
    data_quality: 0.88
    baseline_value: 3.5
    current_value: 1.2
    baseline_deviation: -2.1
    time_scale: "SHORT"
    location: "bedroom"
    explanation: "起身速度明显快于个人基线"
    adapter_version: "fall-adapter-v1"
    source_mode: "MOCK"
    simulated: true

## 五、RiskEvent风险事件

RiskEvent由统一风险引擎生成，前端、萤石工具和报告模块共同使用。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| schema_version | string | 是 | 固定1.0 |
| event_id | string | 是 | 事件唯一标识 |
| resident_id | string | 是 | 老人标识 |
| created_at | datetime | 是 | 创建时间 |
| updated_at | datetime | 是 | 更新时间 |
| primary_domain | enum | 是 | 主风险方向 |
| related_domains | array | 是 | 关联方向 |
| risk_level | enum | 是 | GREEN、YELLOW、ORANGE、RED |
| risk_score | number | 是 | 综合风险分 |
| evidence_ids | array | 是 | 证据链 |
| evidence_summary | array | 是 | 只包含evidence_id、evidence_type、explanation的可解释摘要 |
| time_horizon | string | 是 | TREND、TODAY、IMMINENT |
| recommended_action | string | 是 | 建议动作 |
| intervention_policy | string | 是 | 使用的干预策略 |
| status | enum | 是 | 事件状态 |
| ruleset_version | string | 是 | 风险规则版本 |
| source_mode | enum | 是 | 当前事件核心Evidence的输入来源 |
| simulated | bool | 是 | 任一核心Evidence为模拟数据时必须为true |

`risk_level`和`risk_score`记录事件触发或峰值风险。事件回落后保留原风险等级，通过`status=RESOLVED`和最新`InterventionResult.risk_after`表达风险已经解除。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| schema_version | string | 是 | 固定1.0 |
| result_id | string | 是 | 唯一标识 |
| event_id | string | 是 | 对应风险事件 |
| started_at | datetime | 是 | 干预开始 |
| completed_at | datetime/null | 是 | 完成时间 |
| action_type | string | 是 | voice、push、family_call、screening等 |
| tool_name | string | 是 | ezviz_voice、ezviz_push、family_feedback等 |
| delivery_status | string | 是 | SUCCESS、FAILED、RETRYING |
| resident_response | string/null | 是 | sat_down、stable、no_response等 |
| family_feedback | string/null | 是 | verified、contacted、false_alarm等 |
| risk_after | number/null | 是 | 干预后风险分 |

## 六点一、严格校验和错误处理

- 除Observation的`metadata`外，表中字段均为必填；允许为空的字段必须显式传`null`；
- 未定义字段、字段缺失、类型错误、非法枚举、分数超出0—1或时间不含时区，返回422且不进入状态机；
- `observation_ids`无法追溯、同一ID内容冲突、来源与关联Observation不一致，返回409；
- 相同ID和相同内容重复提交视为幂等重放，不重复创建事件或播放语音；
- 核心对象禁止附加前端展示字段。`title`、`timeline`、`risk_history`等由前端ViewModel管理；
- Pydantic模型位于`contracts/v1/models.py`，是v1.0唯一代码来源；JSON Schema和样例必须由该模型导出。

## 七、适配器输出冻结

### 7.1 赵勇：跌倒Evidence

必须输出：

- rapid_rise；
- slow_rise；
- trunk_sway；
- gait_instability；
- relative_speed_change；
- posture_recovered；
- tracking_lost。

第一阶段先完成可解释特征。LSTM仅作为P1对照模型，不改变Evidence结构。

### 7.2 常易铭：行为与语音Evidence

必须输出：

- activity_range_decline；
- room_transition_decline；
- day_night_rhythm_change；
- unauthorized_visitor；
- unusual_dwell_time；
- fraud_keyword；
- unusual_pacing；
- audio_quality_low。

语音流畅度不得直接输出心理诊断证据。

### 7.3 张薇、冷雨彤：人工确认Evidence

必须输出：

- mental_self_report；
- family_concern；
- voluntary_screening_concern；
- family_contact_completed；
- professional_support_suggested；
- identity_verified；
- false_alarm_confirmed；
- trend_recovered。

人工确认同样使用Evidence或InterventionResult进入系统，不允许直接修改数据库中的风险等级。

### 7.4 系统环境Evidence

必须输出：

- low_illumination；
- high_risk_zone_entry；
- obstacle_occupancy；
- camera_occlusion；
- stream_unavailable。

不输出wet_floor等普通摄像头无法可靠验证的证据。

### 8.1 DeviceAdapter统一行为

DeviceAdapter必须支持以下三档链路，并输出相同的Observation结构：

1. 萤石官方云端接口；
2. 张薇现场电脑采集网关；
3. 云存储片段、本地视频或Mock输入。

算法成员必须支持本地MP4输入。前端只读取后端提供的状态、回放地址和来源标识，不直接保存设备AccessToken。

## 九、错误处理

| 错误 | 处理 |
|---|---|
| confidence缺失 | 拒绝写入并记录400错误 |
| data_quality低于最低门槛 | 生成SYSTEM证据，不参与高等级判断 |
| Evidence重复 | 依据evidence_id幂等处理 |
| 萤石调用失败 | 记录失败并按规则重试，同时保留事件 |
| 视频流中断 | 生成stream_unavailable并通知系统状态 |
| 实时取流不可用 | 自动切换授权事件片段或Mock输入，source_mode必须同步更新 |
| 设备被多人占用 | 拒绝新控制请求并返回409，按飞书预约顺序执行 |
| AccessToken或密钥出现在请求日志 | 立即脱敏并轮换密钥，禁止上传飞书和代码仓库 |
| 规则引擎异常 | 不自动升级红色，记录错误并通知负责人 |
