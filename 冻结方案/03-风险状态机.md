# 03 风险状态机

## 一、设计目标

风险状态机是唯一有权输出绿、黄、橙、红等级的模块。算法、前端、大模型和萤石接口不得自行改变最终风险等级。

规则版本冻结为ruleset-v1.0。

## 二、风险分计算

单条证据有效权重：

> 有效证据分 = severity × confidence × data_quality

综合风险分由以下部分构成：

- 当前窗口内有效证据分；
- 个人基线偏离；
- 不同证据类别的独立性；
- 长、中、短时间尺度；
- 场景修正；
- 当前风险状态；
- 干预后的恢复证据。

权重与门槛通过配置文件管理。研发初期允许使用工程初值，最终版本必须依据验证集校准并记录ruleset_version。

## 三、通用状态

### 3.1 GREEN绿色

进入条件：

- 无持续有效异常；
- 或异常证据置信度、数据质量不足；
- 或风险事件已完成回落观察。

系统行为：

- 不通知；
- 正常更新个人基线；
- 保存脱敏统计。

### 3.2 YELLOW黄色

进入条件满足任一项：

- 同一长期证据连续3天偏离个人基线；
- 两类长期证据在7天窗口内共同持续偏离；
- 家属或老人主动确认需要关注；
- 一项中期异常持续出现但不存在即时危险。

系统行为：

- 不在老人侧即时报警；
- 进入周报；
- 生成可解释原因和建议动作；
- 暂停相关异常时段写入正常基线。

### 3.3 ORANGE橙色

进入条件满足任一项：

- 30秒内出现两类及以上独立跌倒风险证据，且至少一项为高置信度；
- 个人长期或中期风险已为黄色，同时出现一项高置信度临近危险证据；
- 诈骗场景中同时存在非授权访客、异常停留和高风险关键词三类证据；
- 家属人工要求系统进行即时干预。

系统行为：

- 创建RiskEvent；
- 执行语音、推送或家属核验；
- 进入INTERVENING状态；
- 干预完成后进入OBSERVING状态；
- 禁止更新相关个人基线。

### 3.4 RED红色

进入条件满足任一项：

- 明确检测到跌倒，且老人持续无响应；
- 橙色干预后仍持续失衡或继续进入危险区域；
- 萤石设备完成两次干预仍无有效反馈；
- 家属或授权人员人工升级。

系统行为：

- 通知紧急联系人；
- 保留事件片段和证据链；
- 进入人工接管；
- 不自动拨打120；
- 只有授权人员可以关闭或降级红色事件。

心理健康趋势不得由算法自动升级为红色。若老人或家属反馈存在紧急心理安全风险，应提示立即联系专业人员或当地紧急服务，并转人工处置。

## 四、不同场景的进入规则

### 4.1 跌倒核心任务

黄色示例：

- 起身时长、步态稳定性或活动范围连续偏离；
- 单次异常不触发黄色，除非家属确认。

橙色示例：

- 快速起身＋躯干摇晃；
- 躯干摇晃＋低照度＋进入高风险区域；
- 黄色长期状态＋快速起身。

红色示例：

- 跌倒后无响应；
- 干预后持续失衡；
- 事件超过观察上限仍未恢复。

### 4.2 心理健康适配场景

绿色：

- 行为趋势稳定；
- 或短期变化可以被外出、生病、旅行等上下文解释。

黄色：

- 活动范围和昼夜节律持续偏离；
- 加上老人自述、家属反馈或自愿筛查中的关注项。

心理场景一期最高自动等级为黄色。系统输出关怀、筛查和专业评估建议，不输出医学诊断。

### 4.3 诈骗风险适配场景

绿色：

- 正常授权访客；
- 快递或家政短时停留；
- 单个关键词且无其他证据。

黄色：

- 非授权访客长时间停留，但未出现高风险话术；
- 或高风险关键词出现但身份和场景不明确。

橙色：

- 非授权访客＋异常停留＋高风险关键词；
- 或两项证据加老人明显行为偏离。

红色：

- 一期不由算法自动触发诈骗红色；
- 由家属确认发生真实财产危险后人工升级。

## 五、回落规则

### 5.1 跌倒橙色回落

必须同时满足：

- 老人已坐稳、扶稳或恢复稳定行走；
- 连续15秒无新的高风险姿态；
- 语音或推送执行结果已记录；
- 进入至少60秒观察期；
- 综合风险分回落至黄色门槛以下。

观察期结束后标记RESOLVED。若观察期内再次出现危险，重新进入INTERVENING或升级红色。

### 5.2 心理黄色回落

满足任一组合：

- 家属完成联系，且后续趋势停止恶化；
- 老人完成自愿筛查或获得专业建议，并有人工反馈；
- 连续3天活动及作息逐步恢复到个人合理范围。

单次活动增加不足以立即回落。若趋势持续异常，保持黄色。

### 5.3 诈骗事件回落

必须满足：

- 家属完成身份核验；
- 或访客离开且高风险交互结束；
- 家属反馈已记录；
- 无新的诈骗证据。

## 六、提醒冷却与重试

| 场景 | 规则 |
|---|---|
| 黄色周报 | 同类趋势每周最多主动汇总一次，恶化时可更新 |
| 跌倒橙色语音 | 首次失败后重试一次，避免连续轰炸 |
| 家属推送 | 失败按后端策略重试并记录 |
| 诈骗核验 | 同一访客事件只创建一个主事件 |
| 数据质量低 | 不升级风险，生成系统状态提醒 |

## 七、智能体与大模型边界

智能体负责：

- 查询个人记忆；
- 收集结构化Evidence；
- 调用确定性规则引擎；
- 选择已批准干预策略；
- 调用萤石工具；
- 观察干预结果；
- 生成可解释摘要。

大模型可以：

- 将证据转换为家属易懂文案；
- 生成周报初稿；
- 整理事件复盘。

大模型不可以：

- 修改risk_level；
- 绕过状态机；
- 诊断疾病；
- 自动修改ruleset；
- 自动触发120。

## 八、状态机验收用例

| 用例 | 输入 | 预期 |
|---|---|---|
| 单次起身变慢 | 一项长期证据 | 保持绿色并记录 |
| 连续多日活动下降 | 三天长期证据 | 黄色周报 |
| 快速起身＋摇晃 | 两项短时跌倒证据 | 橙色语音干预 |
| 橙色后重新坐稳 | 姿态恢复＋观察期 | 回落并RESOLVED |
| 单个诈骗关键词 | 一项语音证据 | 不进入橙色 |
| 访客＋停留＋关键词 | 三类诈骗证据 | 橙色身份核验 |
| 遮挡导致置信度低 | 低数据质量 | SYSTEM证据，不升级 |
| 跌倒后无响应 | 跌倒＋无响应 | 红色人工接管 |
