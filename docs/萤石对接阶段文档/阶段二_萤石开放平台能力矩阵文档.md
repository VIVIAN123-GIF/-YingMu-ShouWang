## 三、各接口详情

### 3.1 鉴权类

#### 【接口名称】获取AccessToken
- **接口地址**：POST https://open.ys7.com/api/lapp/token/get
- **Content-Type**：application/x-www-form-urlencoded

**请求参数：**

| 参数名 | 类型 | 是否必填 | 说明 |
| ---- | ---- | ---- | ---- |
| appKey | String | 是 | 应用唯一标识 |
| appSecret | String | 是 | 应用密钥 |

**返回参数：**

| 字段名 | 类型 | 说明 |
| ---- | ---- | ---- |
| accessToken | String | 获取到的访问令牌 |
| expireTime | Long | 过期时间戳（毫秒） |

**频率限制：** 无特殊限制，最佳实践为本地缓存，临近过期再刷新
**Token生命周期：** 以接口返回的`expireTime`为准，不能在业务代码中写死固定天数。

**已验证错误码：**
- 200：操作成功
- 10001：参数错误（appKey/appSecret不能为空）
- 10017：appKey不存在
- 10030：appKey和appSecret不匹配

**备注：**
- 新获取Token是否使老Token失效、具体生命周期和刷新策略待以官方文档及实测结果为准
- 用户变更身份信息（密码修改等）后会将旧Token失效
- 报错10002（token过期）时重新获取即可

### 3.2 视频取流类（云直播）

#### 【接口名称】获取直播播放地址
- **接口地址**：POST https://open.ys7.com/api/lapp/v2/live/address/get
- **Content-Type**：application/x-www-form-urlencoded

**请求参数：**

| 参数名 | 类型 | 是否必填 | 说明 |
| ---- | ---- | ---- | ---- |
| accessToken | String | 是 | 授权令牌 |
| deviceSerial | String | 是 | 设备序列号，限50字符 |
| channelNo | Integer | 否 | 通道号，默认1 |
| protocol | Integer | 否 | 流播放协议：1-ezopen、2-hls、3-rtmp、4-flv、5-lhls，默认1 |
| code | String | 否 | ezopen协议设备视频加密密码 |
| expireTime | Integer | 否 | 过期时长（秒），针对hls/rtmp/flv有效，30秒-720天 |
| type | String | 否 | 地址类型：1-预览、2-本地录像回放、3-云存储录像回放，默认1 |
| quality | Integer | 否 | 预览清晰度：1-高清（主码流）、2-流畅（子码流） |

**2026-07-30 19:54—19:55 最新三轮实机结果：**
- 第1轮：HLS 返回 60019“加密已开启”，携带本地验证码回退 ezopen 后 HTTP 200、业务码 200，取得临时地址；两次地址请求总耗时 11861 ms
- 第2轮：抓图请求超时，播放地址阶段跳过
- 第3轮：播放地址请求超时，未进入 ezopen 回退
- 临时地址：第1轮取得但不保存；第2、3轮未取得
- 结论：ezopen 地址获取能力已有一次真实成功证据，但完整链路仅 1/3 成功、`consistent=false`；不能声明 HLS 或实际视频播放成功

**频率限制：** 待实测确认

**错误码：** HLS 观测到 60019，平台脱敏消息为“加密已开启”；本地验证码配合 ezopen 回退可取得地址，但不把该结果外推为 HLS 或实际播放能力

**备注：**
- 无法获取永久有效期播放地址
- 支持多种协议：ezopen（萤石私有）、hls、rtmp、flv、lhls
- 项目推荐使用 flv 或 hls 协议，便于前端网页播放

### 3.4 消息推送类

#### 【方式一】WebHook回调推送（推荐）
- **机制**：萤石平台主动POST消息到开发者提供的回调地址
- **配置位置**：开放平台控制台 → 消息推送 → 配置WebHook
- **回调要求**：
  - 必须支持HTTPS（也支持HTTP）
  - 接收成功必须返回 HTTP 200
  - 超过2秒未响应或非200响应视为推送失败
  - 可配置失败重试次数

**可推送消息类型：**
- 设备上下线消息
- 告警消息（移动侦测、人体检测等）
- 呼叫消息（ys.calling，门铃类设备）
- ISAPI透传消息

**消息体格式：** JSON格式，包含设备序列号、事件类型、时间戳等字段

#### 【方式二】消息队列（MQ）消费
- 创建消费者：/api/lapp/mq/v2/consumer/{consumerName}
- 适合高并发、需要消息持久化的场景

#### 【方式三】主动查询告警消息
- 接口获取历史告警记录列表
- 支持按设备、按时间范围查询

**备注：**
- 消息推送服务为付费服务，有资源包规格
- 项目初期建议使用WebHook方式，开发简单
- 跌倒检测事件如果是平台AI能力产生的，可通过告警消息推送；如果是自实现算法，则不需要

**2026-08-15 现场结果：**
- 萤石平台真实 `ys.alarm` 告警成功到达 `POST /api/v1/webhooks/ezviz`，后端返回 HTTP 200；
- 告警已幂等入库并创建处理任务，Worker 完成真实抓拍和私有 Asset 入库；
- 公共响应和交付记录不包含 Token、完整设备序列号或临时图片 URL；
- 单张真实抓拍只用于当前姿态和画面质量，不作为快速起身、连续摇摆等时序 Evidence。

### 3.5 语音对讲/云通话类

#### 【重要说明】萤石语音能力分类
萤石的语音能力分为两种，需要重点区分：

**1. 设备端语音对讲（双向）**
- 主要通过端侧SDK实现（Android/iOS/Windows SDK）
- 流程：创建对讲播放器 → 启动对讲 → 停止对讲 → 释放
- 纯服务端API无法直接发起双向对讲

**2. 云通话（ERTC）**
- 接口地址：https://open.ys7.com/api/service/rtc/call/request
- 基于RTC实时音视频技术
- 需要创建RTC应用、创建房间、邀请设备
- 适合门铃、门禁等呼叫场景

**3. 语音喊话/单向语音播报**
- 部分设备支持服务端触发语音播报
- 具体能力待现场实机调用验证

**待验证问题（现场实机确认）：**
- 摄像头型号是否支持服务端API触发语音播放？
- 是否可以通过接口下发语音文件或TTS文字转语音？
- 双向对讲是否必须通过SDK实现？

**风险提示：**
如果纯服务端API无法触发语音对讲，需要调整方案：
- 方案A：使用SDK方式在前端页面实现对讲
- 方案B：仅保留视频预览+文字告警，语音功能降级

## 六、开发建议

1. **Token管理**：统一封装Token获取与自动刷新逻辑，全局缓存，禁止每次业务请求都获取新Token
2. **错误处理**：统一封装萤石API调用，拦截常见错误码（token过期、设备离线等）做统一处理
3. **设备状态轮询**：建议定时轮询设备在线状态，异常时告警
4. **消息推送**：优先采用WebHook方式接收设备事件，开发成本低
5. **语音功能**：预留降级方案，语音不可用时使用明确标注的 `mock_voice`、文字告警和已核验抓图/授权回放；实时视频未验证前不得写成视频预览成功
6. **Mock开发**：未完成实机验证的能力继续保留 Mock 接口，业务侧使用 `source_mode` 和失败日志区分真实调用与降级结果

本次结果不改变播放与语音边界：临时播放地址仍为“部分验证或未稳定验证”，不能宣称网页实时视频播放能力已经完成验证；服务端语音继续保持“未验证”，干预使用明确标记的 `mock_voice` 或 `local_text` 降级工具。

### 能力边界

1. 真实抓拍成功不等于临时播放地址或网页实时播放成功。
2. 单张抓拍不能生成快速起身、连续摇摆和步态变化等时序 Evidence。
3. `qwen3.6-flash` 只解释结构化 RiskEvent、Evidence 和基线摘要，不参与风险等级判定。
4. 授权 MP4 闭环明确属于 `RECORDED_REPLAY/simulated=true`，不冒充实时设备连续视频。
5. `mock_voice` 和 `local_text` 是显式降级工具，不代表萤石服务端语音已经验证。
