## 三、各接口详情

### 3.1 鉴权类

#### 【接口名称】获取AccessToken
- **接口地址**：POST https://open.ys7.com/api/lapp/token/get
- **Content-Type**：application/x-www-form-urlencoded

**请求参数：**

| 参数名 | 类型 | 是否必填 | 说明 |
| ---- | ---- | ---- | ---- |
| appKey | String | 是 | 应用唯一标识 |
| appSecret | String | 是 | 应用密钥 |

**返回参数：**

| 字段名 | 类型 | 说明 |
| ---- | ---- | ---- |
| accessToken | String | 获取到的访问令牌 |
| expireTime | Long | 过期时间戳（毫秒） |

**频率限制：** 无特殊限制，最佳实践为本地缓存，临近过期再刷新
**token有效期：** 7天（注意：不是之前以为的2小时，官方文档标注为7天）

**已验证错误码：**
- 200：操作成功
- 10001：参数错误（appKey/appSecret不能为空）
- 10017：appKey不存在
- 10030：appKey和appSecret不匹配

**备注：**
- 新获取Token不会使老Token失效，每个Token独立拥有7天生命周期
- 用户变更身份信息（密码修改等）后会将旧Token失效
- 报错10002（token过期）时重新获取即可

### 3.2 视频取流类（云直播）

#### 【接口名称】获取直播播放地址
- **接口地址**：POST https://open.ys7.com/api/lapp/v2/live/address/get
- **Content-Type**：application/x-www-form-urlencoded

**请求参数：**

| 参数名 | 类型 | 是否必填 | 说明 |
| ---- | ---- | ---- | ---- |
| accessToken | String | 是 | 授权令牌 |
| deviceSerial | String | 是 | 设备序列号，限50字符 |
| channelNo | Integer | 否 | 通道号，默认1 |
| protocol | Integer | 否 | 流播放协议：1-ezopen、2-hls、3-rtmp、4-flv、5-lhls，默认1 |
| code | String | 否 | ezopen协议设备视频加密密码 |
| expireTime | Integer | 否 | 过期时长（秒），针对hls/rtmp/flv有效，30秒-720天 |
| type | String | 否 | 地址类型：1-预览、2-本地录像回放、3-云存储录像回放，默认1 |
| quality | Integer | 否 | 预览清晰度：1-高清（主码流）、2-流畅（子码流） |

**返回参数：** 待实测确认

**频率限制：** 待实测确认

**错误码：** 待实测确认

**备注：**
- 无法获取永久有效期播放地址
- 支持多种协议：ezopen（萤石私有）、hls、rtmp、flv、lhls
- 项目推荐使用 flv 或 hls 协议，便于前端网页播放

### 3.4 消息推送类

#### 【方式一】WebHook回调推送（推荐）
- **机制**：萤石平台主动POST消息到开发者提供的回调地址
- **配置位置**：开放平台控制台 → 消息推送 → 配置WebHook
- **回调要求**：
  - 必须支持HTTPS（也支持HTTP）
  - 接收成功必须返回 HTTP 200
  - 超过2秒未响应或非200响应视为推送失败
  - 可配置失败重试次数

**可推送消息类型：**
- 设备上下线消息
- 告警消息（移动侦测、人体检测等）
- 呼叫消息（ys.calling，门铃类设备）
- ISAPI透传消息

**消息体格式：** JSON格式，包含设备序列号、事件类型、时间戳等字段

#### 【方式二】消息队列（MQ）消费
- 创建消费者：/api/lapp/mq/v2/consumer/{consumerName}
- 适合高并发、需要消息持久化的场景

#### 【方式三】主动查询告警消息
- 接口获取历史告警记录列表
- 支持按设备、按时间范围查询

**备注：**
- 消息推送服务为付费服务，有资源包规格
- 项目初期建议使用WebHook方式，开发简单
- 跌倒检测事件如果是平台AI能力产生的，可通过告警消息推送；如果是自实现算法，则不需要

### 3.5 语音对讲/云通话类

#### 【重要说明】萤石语音能力分类
萤石的语音能力分为两种，需要重点区分：

**1. 设备端语音对讲（双向）**
- 主要通过端侧SDK实现（Android/iOS/Windows SDK）
- 流程：创建对讲播放器 → 启动对讲 → 停止对讲 → 释放
- 纯服务端API无法直接发起双向对讲

**2. 云通话（ERTC）**
- 接口地址：https://open.ys7.com/api/service/rtc/call/request
- 基于RTC实时音视频技术
- 需要创建RTC应用、创建房间、邀请设备
- 适合门铃、门禁等呼叫场景

**3. 语音喊话/单向语音播报**
- 部分设备支持服务端触发语音播报
- 具体能力待硬件到货后验证

**待验证问题（硬件到货后确认）：**
- 摄像头型号是否支持服务端API触发语音播放？
- 是否可以通过接口下发语音文件或TTS文字转语音？
- 双向对讲是否必须通过SDK实现？

**风险提示：**
如果纯服务端API无法触发语音对讲，需要调整方案：
- 方案A：使用SDK方式在前端页面实现对讲
- 方案B：仅保留视频预览+文字告警，语音功能降级

## 四、通用错误码汇总

| 错误码 | 说明 | 处理建议 |
| ---- | ---- | ---- |
| 200 | 操作成功 | 正常业务处理 |
| 10001 | 参数错误 | 检查请求参数完整性、格式 |
| 10002 | accessToken过期或无效 | 重新获取accessToken |
| 10017 | appKey不存在 | 检查appKey是否正确 |
| 10030 | appKey与appSecret不匹配 | 检查密钥配对 |
| 20002 | 设备不存在 | 检查设备序列号、是否已绑定 |
| 20007 | 设备不在线 | 检查设备通电、联网状态 |
| 20014 | 设备响应超时 | 稍后重试或检查设备网络 |

*注：完整错误码待后续逐步补充验证*

## 六、开发建议

1. **Token管理**：统一封装Token获取与自动刷新逻辑，全局缓存，禁止每次业务请求都获取新Token
2. **错误处理**：统一封装萤石API调用，拦截常见错误码（token过期、设备离线等）做统一处理
3. **设备状态轮询**：建议定时轮询设备在线状态，异常时告警
4. **消息推送**：优先采用WebHook方式接收设备事件，开发成本低
5. **语音功能**：预留降级方案，语音不可用时自动切换为文字告警+视频预览
6. **Mock开发**：硬件到货前，基于本文档开发Mock接口，业务侧可先行对接调试
