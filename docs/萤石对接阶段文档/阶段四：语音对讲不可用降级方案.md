# 阶段四：语音对讲不可用降级方案文档
## 一、方案目标
当前无真实摄像头硬件，基于Mock接口模拟语音调用失败场景；摄像头到货后适配真实设备报错，保障系统在语音对讲功能失效时不崩溃，提供完整降级、重试、告警、日志流程。

## 二、语音接口失效触发场景
1. 业务侧传入的设备序列号离线（Mock标识：offline）
2. 设备硬件不支持语音对讲功能（Mock标识：novoice）
3. accessToken过期、鉴权失败
4. 萤石平台接口限流、服务临时异常
5. 网络超时、接口请求失败

## 三、失败重试策略
1. 最大重试次数：3次
2. 重试间隔：首次2s、第二次3s、第三次5s
3. 终止重试条件：
   - 达到最大重试次数
   - 返回固定业务错误码（设备不存在/设备不支持语音/密钥错误，无需重试）
4. 重试期间行为：前端不阻塞，后台静默重试，不重复弹窗提示用户

## 四、语音功能失效业务降级逻辑
1. 停止下发语音喊话指令，不再调用 `/voice/send` 接口
2. 保留视频预览功能正常运行，视频流不受语音故障影响
3. 切换文字告警替代语音提醒：
   - 前端弹窗展示文字预警消息
   - 后台持久化告警记录，存入数据库
4. 关闭语音相关联动逻辑，避免级联报错

## 五、异常日志上报规则
1. 日志字段：时间戳、accessToken、设备序列号、报错code、报错信息、重试次数
2. 分级记录：
   - WARN：单次语音调用失败，未达重试上限
   - ERROR：3次重试全部失败，语音功能完全不可用
3. 日志留存：永久保存，硬件实测后用于对比真实设备异常日志

## 六、前端交互提示规范
1. 单次调用失败：底部轻提示「语音播报暂时失败，已文字提醒」，无弹窗打扰
2. 多次重试失败：弹窗提示「设备语音功能异常，请查看设备状态」，附带设备编号
3. 设备不支持语音型号：永久隐藏语音喊话按钮，仅保留视频查看

## 七、硬件到货后适配补充项
1. 对接真实萤石接口，采集真实语音报错码，更新文档错误码对照表
2. 根据真实设备网络延迟调整重试间隔
3. 验证老旧摄像头无语音硬件的真实返回逻辑，同步更新Mock模拟规则
4. 补充语音喊话成功/失败的真实报文归档
