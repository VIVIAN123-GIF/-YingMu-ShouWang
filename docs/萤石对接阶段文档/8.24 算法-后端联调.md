**四、正常样本**

在操作终端设置实际路径和录制时间：

```cmd
set "NORMAL_MP4=D:\private-media\authorized-normal.mp4"
set "NORMAL_TIME=2026-08-20T09:30:00+08:00"
```

提交：

```cmd
.venv\Scripts\python.exe -m dotenv -f .env run --override -- .venv\Scripts\python.exe scripts\enqueue_recorded_replay.py --input "%NORMAL_MP4%" --resident-id "resident-redacted-001" --captured-at "%NORMAL_TIME%"
```

预期首先返回：

```text
result=CREATED
status=CAPTURED
source_mode=RECORDED_REPLAY
simulated=true
```

随后观察终端 2，等待任务完成，再查询：

```cmd
curl.exe -s "http://127.0.0.1:8000/api/v1/alarms/processing?resident_id=resident-redacted-001&limit=20"
```

正常样本通过标准：

- GAIT、TRAJECTORY 均未 `FAILED`；
- 至少生成 Observation；
- 允许任务为 `NO_EVIDENCE`；
- 允许符合合同的 `LOW_QUALITY`；
- 不得生成虚假风险 Evidence；
- `FEATURE_INPUT_INVALID` 不通过。

**五、风险样本**

```cmd
set "RISK_MP4=D:\private-media\authorized-risk.mp4"
set "RISK_TIME=2026-08-20T10:00:00+08:00"

.venv\Scripts\python.exe -m dotenv -f .env run --override -- .venv\Scripts\python.exe scripts\enqueue_recorded_replay.py --input "%RISK_MP4%" --resident-id "resident-redacted-001" --captured-at "%RISK_TIME%"
```

等待两个 Worker处理，然后查询：

```cmd
curl.exe -s "http://127.0.0.1:8000/api/v1/alarms/processing?resident_id=resident-redacted-001&limit=20"
curl.exe -s "http://127.0.0.1:8000/api/v1/events?resident_id=resident-redacted-001"
```

风险样本通过标准：

- 生成算法方事先声明的 Evidence；
- Evidence 引用本批次 Observation；
- 生成 RiskEvent 和 RuleTrace；
- 创建 Agent Job；
- Agent Job完成，或有明确可解释的降级原因；
- 风险样本只得到 `NO_EVIDENCE` 时不算通过。

**六、幂等复验**

原样再次执行风险样本命令，路径、居民 ID和录制时间都不能改变。

预期：

- 返回 `EXISTING` 或等价幂等结果；
- Asset、任务、Observation、Evidence ID保持不变；
- 不重复创建 RiskEvent；
- 不重复创建 Agent Job。

**七、失败时怎么分工**

- `ModuleNotFoundError`：后端检查 `PYTHONPATH`，算法方检查包结构。
- `FEATURE_INPUT_INVALID`、`no_pose_detected`：算法方检查门槛、姿态检测和样本质量。
- AdapterBatch 合同校验失败：算法方修正输出。
- 数据库写入 `409/422`：后端检查合同继承、ID和幂等约束。
- 风险样本无 Evidence：先与预期 AdapterBatch 对照，不能手工改库。
- 萤石媒体出现固定提示片：先查询主、子码流编码。设备为 H.265 时应切换为 H.264 后复测，
  不再直接归因为 CDN 或算法方失败。
