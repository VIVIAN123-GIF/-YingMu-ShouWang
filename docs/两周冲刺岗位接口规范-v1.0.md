# 两周冲刺岗位接口规范 v1.0

## 1. 文档目的

本文档用于冻结“萤目守望”最后两周的岗位边界、数据合同、调用顺序和验收标准。所有成员以本规范作为联调依据，不再通过口头约定临时增加字段、风险等级或接口。

核心决策：

> 统一的是数据合同、风险引擎和调用入口，不是底层模型。

项目采用垂直模型分别感知、统一 `Observation/Evidence` 入库、确定性状态机裁决、大模型智能体解释的混合架构：

```text
萤石 Webhook / 抓拍 / 授权视频 / 音频
                    |
                    v
            Asset + AlgorithmJob
                    |
        +-----------+-----------+
        |                       |
        v                       v
共享姿态提取器             专用 ASR
  |          |                 |
  v          v                 v
GaitAdapter  TrajectoryAdapter LanguageAdapter
        \        |        /
         \       |       /
          Observation / Evidence
                    |
                    v
        个人基线 + ruleset-v1.0
                    |
                    v
                RiskEvent
                    |
          +---------+---------+
          |                   |
          v                   v
     智能体解释          干预与恢复状态机
```

## 2. 当前状态和本期边界

### 2.1 已完成

- 萤石 Webhook 已部署；后续只做真实告警回归、日志归档和幂等验证。
- `Asset`、`Observation`、`Evidence`、`RiskEvent`、`InterventionResult` 已有后端模型和接口。
- MediaPipe 33 点姿态、跌倒 Evidence 样例、30 秒/24 小时/7 日记忆、个人基线和规则状态机已有实现。
- 前端静态页面大部分完成。

### 2.2 P0 待完成

- Webhook 任务自动调用萤石抓拍，并在临时 URL 失效前下载图片、登记 Asset。
- Worker 从 `WAITING_ALGORITHM` 继续调用算法适配器。
- 步态、轨迹、语言模块统一生成合法的 Observation/Evidence。
- 智能体只解释 RiskEvent，不参与安全等级裁决。
- “我已坐稳”、姿态恢复、观察期、解除或升级形成闭环。
- 前端展示 `LIVE_DEVICE`、`RECORDED_REPLAY`、`PUBLIC_DATASET`、`MOCK` 的真实来源。

### 2.3 明确不做

- 不训练或微调新的深度时序模型。
- 不让多模态大模型直接读取整段视频并决定红橙黄绿。
- 不建设三个独立微服务；三个算法以本地适配器接入现有 `AlgorithmGateway`。
- 不宣称未经标注和校准的数值是“未来跌倒概率”；统一称为“工程风险指数”。
- 不自动识别普通摄像机无法可靠验证的地面湿滑；允许将已知湿滑位置人工标定为风险区域。

## 3. 责任边界

| 岗位 | 第一负责人 | 可写入的业务对象 | 禁止事项 |
|---|---|---|---|
| 步态算法 | 赵同学 | Observation、FALL Evidence | 不写数据库，不提交 risk_level，不调用干预接口 |
| 语言算法 | 常同学 | Observation、FRAUD/SYSTEM Evidence、居民回应候选 | 不凭单句语音关闭事件，不直接诊断心理疾病 |
| 行为轨迹 | 常同学 | Observation、MENTAL/SYSTEM/FALL Evidence | 不自行修改个人基线，不直接升级红色 |
| 萤石平台 | 张同学 | PlatformSnapshotResult、设备能力状态 | 不向前端暴露 Token、验证码、完整序列号和临时 URL |
| 智能体 | 张同学 | AgentExplanation | 不创建或修改 RiskEvent，不绕过状态机执行安全裁决 |
| 后端与风险引擎 | 冷同学 | 全部持久化对象和 RuleTrace | 不伪造算法结果，不把 Mock 记录标为 LIVE_DEVICE |
| 前端与验收 | 陈同学 | InterventionResult、FamilyFeedback 请求 | 不直接调用萤石开放平台，不在浏览器保存平台凭证 |
| 设备与素材 | 蔡同学 | SceneCalibration、CaptureManifest、授权记录 | 不修改算法结论，不拍摄无保护的真实跌倒 |

## 4. 统一版本和通用规则

### 4.1 版本

- 四对象合同：`schema_version = "1.0"`。
- 风险规则：`ruleset-v1.0`。
- 内部任务合同：`algorithm-job/1.0`。
- 内部适配器结果：`adapter-batch/1.0`。
- 每个算法必须提供独立的 `adapter_version`，例如 `gait-adapter-v1.0.0`。

### 4.2 时间和分数

- 所有时间使用 ISO 8601 且必须带时区，例如 `2026-08-15T09:30:00+08:00`。
- `confidence`、`data_quality`、`severity`、`risk_score` 范围均为 `[0, 1]`。
- 当前质量门槛：`confidence >= 0.70` 且 `data_quality >= 0.70`。
- 高置信组合门槛：`confidence >= 0.80`。
- 当前记忆窗口：即时/短时使用 30 秒，背景使用 24 小时，长期基线使用 7 日。
- 当前恢复门槛：稳定姿态持续 15 秒，随后观察 60 秒。

### 4.3 来源语义

| source_mode | 含义 | simulated 示例 |
|---|---|---|
| `LIVE_DEVICE` | 当前萤石设备实时触发的抓拍或流 | 现场按脚本模拟动作时可为 `true` |
| `RECORDED_REPLAY` | 已授权的萤石实拍录像回放 | 摆拍动作通常为 `true`，自然历史事件可为 `false` |
| `PUBLIC_DATASET` | URFD 等公开数据 | 按数据集内容标记，通常为 `false` |
| `MOCK` | 构造 JSON、固定页面数据或 Mock 工具 | 必须为 `true` |

`source_mode` 描述数据传输来源，`simulated` 描述事件或结果是否人为构造，两者不得互相替代。

### 4.4 幂等 ID

- 同一输入窗口重试时必须生成相同 ID。
- 推荐 ID：`obs-{module}-{asset_hash}-{feature}-{window_start_ms}`。
- 推荐 ID：`evi-{module}-{asset_hash}-{type}-{window_start_ms}`。
- 同一 ID、相同内容重试返回 200；同一 ID、不同内容返回 409。
- 算法重试不得使用随机 UUID 生成新的 Observation/Evidence。

## 5. 岗位间内部接口

### 5.1 AlgorithmJob：冷同学到算法成员

该对象只在后端和本地算法进程之间传递，不向浏览器公开。

```json
{
  "schema_version": "algorithm-job/1.0",
  "job_id": "job-alarm-task-001",
  "correlation_id": "alarm-task-001",
  "resident_id": "resident-001",
  "asset_id": "asset-live-snapshot-001",
  "media_type": "VIDEO",
  "media_locator": "C:/authorized-media/event-001.mp4",
  "captured_at": "2026-08-15T09:30:00+08:00",
  "source_mode": "RECORDED_REPLAY",
  "simulated": true,
  "location": "living_room",
  "camera_position_id": "living-room-c6c-v1",
  "scene_config_id": "scene-living-room-v1",
  "requested_modules": ["GAIT", "TRAJECTORY"],
  "deadline_ms": 8000
}
```

字段约束：

| 字段 | 约束 |
|---|---|
| `media_type` | `IMAGE`、`VIDEO`、`AUDIO` 之一 |
| `media_locator` | 仅允许后端可访问的本地授权路径或短期内部地址，不允许萤石 Token |
| `requested_modules` | `GAIT`、`TRAJECTORY`、`LANGUAGE` 的非空子集 |
| `deadline_ms` | 单模块建议 8000 ms；超时由 AlgorithmGateway 隔离 |
| `source_mode/simulated` | 所有输出必须原样继承 |

图片任务只允许输出当前姿态、光照和质量 Observation，不能输出快速起身、连续摇摆、路线偏离等时序结论。

### 5.2 AdapterBatch：算法成员到冷同学

```json
{
  "schema_version": "adapter-batch/1.0",
  "job_id": "job-alarm-task-001",
  "module": "GAIT",
  "adapter_version": "gait-adapter-v1.0.0",
  "status": "SUCCESS",
  "started_at": "2026-08-15T09:30:01+08:00",
  "completed_at": "2026-08-15T09:30:03+08:00",
  "observations": [],
  "evidences": [],
  "resident_response_candidate": null,
  "diagnostics": {
    "elapsed_ms": 1860,
    "valid_frame_ratio": 0.91,
    "model_name": "mediapipe-pose-heavy"
  },
  "error": null
}
```

`status` 只能为：

| 状态 | 含义 | 输出要求 |
|---|---|---|
| `SUCCESS` | 推理成功 | Observation 可非空；没有风险时 Evidence 可为空 |
| `NO_EVIDENCE` | 推理成功但没有形成证据 | 必须至少有质量 Observation |
| `LOW_QUALITY` | 输入不足以判断 | 输出 `tracking_lost`、`audio_quality_low` 等质量证据 |
| `FAILED` | 模块异常 | `error` 必填，不得伪造 Observation/Evidence |

`diagnostics` 只用于日志和性能验收，不进入四对象合同。`resident_response_candidate` 仅允许语言模块填写：

```json
{
  "intent": "STABLE",
  "confidence": 0.92,
  "transcript_observation_id": "obs-language-asset001-intent-0"
}
```

`intent` 只能为 `STABLE`、`HELP`、`UNCERTAIN`。无声音由后端超时逻辑判断，语言模型不得把静音直接等同于危险。

## 7. 张同学：萤石平台接口

### 7.1 Webhook

- 外部入口：`POST /api/v1/webhooks/ezviz`。
- 成功响应必须保持萤石要求的最小格式：`{"messageId":"原始消息ID"}`。
- Webhook 只验签、去重、落库、入队，必须在 2 秒内返回。
- 抓拍和算法不得在 Webhook 请求线程中同步执行。
- `ys.test.msg` 和 `ys.shadow.change` 只确认，不创建风险任务。

### 7.2 PlatformSnapshotResult：张同学到冷同学

萤石 `/api/lapp/device/capture` 成功后统一为：

```json
{
  "schema_version": "platform-snapshot/1.0",
  "request_id": "ezviz-capture-20260815-001",
  "device_ref": "device-redacted-a13f",
  "channel_no": 1,
  "captured_at": "2026-08-15T09:30:00+08:00",
  "source_mode": "LIVE_DEVICE",
  "simulated": false,
  "temporary_url": "INTERNAL_ONLY",
  "expires_at": null,
  "provider_latency_ms": 3650
}
```

边界：

- `temporary_url` 只在进程内交给冷同学的下载器，不入日志、不入 RuleTrace、不返回前端。
- 冷同学下载完成后计算 SHA-256、内容类型、字节数并创建 Asset。
- Token 过期重取一次；设备离线不重试；网络超时按 2 秒、4 秒退避，最多 3 次。
- 抓拍失败不能伪造 `LIVE_DEVICE` 图片；任务进入 `RETRY` 或 `FAILED`。

## 8. 赵同学：GaitAdapter 接口

### 8.1 输入

- 接受 `IMAGE` 和 `VIDEO` AlgorithmJob。
- `IMAGE` 只输出人体是否存在、关键点质量、当前躯干角度等 Observation。
- `VIDEO` 输出时序微特征和 Evidence。
- 首版继续使用 MediaPipe；RTMPose 评测不得超过 1 个工作日。

### 8.2 Observation.feature_name 冻结

| feature_name | unit | 含义 | 可映射 Evidence |
|---|---|---|---|
| `rise_duration_s` | `second` | 完成起身所需时间 | rapid_rise、slow_rise |
| `hip_vertical_speed_norm_s` | `frame_height_per_second` | 髋中心归一化上移速度 | rapid_rise |
| `trunk_sway_angle_deg` | `degree` | 时间窗内躯干最大摆幅 | trunk_sway |
| `com_offset_norm` | `frame_width_ratio` | 近似重心相对支撑中心偏移 | gait_instability |
| `step_speed_norm_s` | `body_scale_per_second` | 归一化相对步速 | relative_speed_change |
| `step_asymmetry_ratio` | `ratio` | 左右步幅差异 | gait_instability |
| `turn_angular_velocity_deg_s` | `degree_per_second` | 急转身角速度 | gait_instability |
| `support_distance_norm` | `frame_diagonal_ratio` | 手腕或身体中心到支撑区距离 | gait_instability |
| `stable_posture_duration` | `second` | 连续稳定时长 | posture_recovered |
| `stable_trunk_angle_deg` | `degree` | 恢复阶段躯干角度 | posture_recovered |
| `valid_frame_ratio` | `ratio` | 有效姿态帧比例 | tracking_lost |

细粒度前兆放在 Observation，不在两周内新增同名 Evidence。赵同学必须将其映射到后端现有枚举。

### 8.3 Evidence 映射

| evidence_type | 必需 Observation | 说明 |
|---|---|---|
| `rapid_rise` | rise_duration_s、hip_vertical_speed_norm_s | 单独出现只等待第二条独立证据 |
| `slow_rise` | rise_duration_s | 长期机能变化证据，不等同即时跌倒 |
| `trunk_sway` | trunk_sway_angle_deg | 与 rapid_rise 在 30 秒内组合可触发橙色 |
| `gait_instability` | com_offset_norm、step_asymmetry_ratio、turn_angular_velocity_deg_s 或 support_distance_norm | explanation 必须说明具体微特征 |
| `relative_speed_change` | step_speed_norm_s | 必须与个人基线比较 |
| `posture_recovered` | stable_posture_duration、stable_trunk_angle_deg | current_value 为稳定秒数，baseline_value 固定 15.0 |
| `tracking_lost` | valid_frame_ratio | 低质量证据不得触发风险升级 |

### 8.5 赵同学验收

- 同一片段重复运行三次，Evidence 类型和数值误差在约定范围内。
- 正常起身只产生正常 Observation 或基线样本，不产生橙色事件。
- 快速起身加摇摆能够产生两条独立 Evidence。
- 低照度、遮挡和出画产生质量证据，不强行输出危险动作。
- 输出通过 `scripts/validate_algorithm_samples.py` 和后端 201/200 幂等测试。

## 9. 常同学：TrajectoryAdapter 接口

### 9.1 输入和共享姿态

- 直接复用赵同学的关键点或髋中心轨迹，不重复运行同一套姿态模型。
- 读取蔡同学的 SceneCalibration。
- 单人固定机位默认以髋中心作为轨迹点；多人场景不在 P0 范围。

### 9.2 Observation.feature_name 冻结

| feature_name | unit | 映射 |
|---|---|---|
| `danger_zone_entry` | null/bool | high_risk_zone_entry |
| `danger_zone_dwell_s` | second | high_risk_zone_entry |
| `trajectory_intersects_obstacle` | null/bool | high_risk_zone_entry，引用 obstacle_occupancy 上下文 |
| `support_zone_distance_norm` | frame_diagonal_ratio | gait_instability |
| `route_deviation_score` | ratio | unusual_pacing 或 activity_range_decline |
| `pacing_reversal_count` | count | unusual_pacing |
| `activity_range_ratio` | ratio | activity_range_decline |
| `room_transition_count` | count_per_day | room_transition_decline |

### 9.3 Evidence 映射

- 实时进入危险区：`risk_domain=SYSTEM`、`evidence_type=high_risk_zone_entry`。
- 障碍物区域被占用：`SYSTEM/obstacle_occupancy`；它是环境上下文，不能单独判跌倒。
- 路线穿越障碍：以 `high_risk_zone_entry` 表示，并在 explanation 写明穿越了哪个已标定区域。
- 扶手距离过远：形成 `FALL/gait_instability`，引用 `support_zone_distance_norm` Observation。
- 长期活动范围下降：`MENTAL/activity_range_decline`。
- 异常往返：`MENTAL/unusual_pacing`。

### 9.4 常同学轨迹验收

- 相同轨迹和场景配置重复运行得到相同区域判断。
- 场景配置缺失时返回 `FAILED/SCENE_CONFIG_MISSING`，不得猜测危险区。
- 正常路线不生成危险区 Evidence。
- 至少有一条路线穿越或危险区停留场景能进入统一事件链。
- 展示时明确“人工固定机位场景标定”，不宣称通用场景理解模型。

### 11.2 Worker 编排顺序

```text
PENDING
  -> PROCESSING
  -> CAPTURED
  -> ALGORITHM_PROCESSING
  -> COMPLETED / NO_EVIDENCE

任一步临时失败 -> RETRY
达到上限 -> FAILED
```

现有 `WAITING_ALGORITHM` 只能作为过渡兼容状态；接入适配器后不得成为终态。

处理要求：

1. 下载萤石临时图片并验证 HTTP 200、图片 Content-Type、非零字节。
2. 登记 Asset 后再创建引用该 `asset_id` 的 Observation。
3. 通过 AlgorithmGateway 调用三个适配器；一个失败不取消其他模块。
4. 先写入所有 Observation，成功后再写 Evidence。
5. Evidence 写入会自动调用风险引擎，算法不得重复调用 `/risk/evaluate`。
6. 保存模块耗时和错误码，但不得把 Token、完整路径和转写隐私写入 RuleTrace。

### 11.3 基线接口和更新权限

个人基线只由后端更新。允许进入基线的样本必须同时满足：

- Evidence 类型属于冻结的 baseline sample 类型。
- `confidence/data_quality >= 0.70`。
- Asset 已授权且来源一致。
- 当前没有活动中的橙色或红色事件。
- 人工复核为正常，或事件已完成恢复和观察。

算法只能提交当前值和候选基线样本，不能提交新的 median、MAD 或基线状态。

### 11.4 HTTP 状态码

| 状态码 | 含义 |
|---|---|
| 201 | 首次创建成功 |
| 200 | 查询成功或同内容幂等重放 |
| 409 | ID冲突、Observation缺失、来源不一致、授权不完整 |
| 422 | 字段缺失、枚举非法、时间无时区、Evidence类型不合法 |
| 503 | 萤石、算法或控制能力暂不可用 |

## 15. P0 合同冲突和修复决策

以下问题在当前代码中已经存在，联调前必须处理：

### 15.1 无响应和持续不稳

`contracts/v1/decision.py` 已使用 `no_response`、`persistent_instability` 进行红色升级，但 `backend/schemas/evidence.py` 当前不接受这两个类型。

两周内的最小修复决策：

- 将二者加入 `RiskDomain.FALL` 的后端允许集合和 canonical contract。
- 它们只能由冷同学的反馈/聚合服务生成，赵、常两位算法成员不得直接提交。
- `no_response` 来源于活动事件干预后的后端超时；`persistent_instability` 来源于多次有效步态危险证据聚合。
- 完成合同、Schema、样例和测试同步后才能在答辩中演示无响应升级。

### 15.2 质量门控类型

后端内部会生成 `quality_gate_failed` SYSTEM Evidence，但公开 Evidence 枚举未包含该类型。冷同学应统一内部对象和响应模型，确保事件详情序列化不会失败。

### 15.3 前端恢复接口

`frontend/src/services/repository.js` 当前构造了 InterventionResult，却调用 `/events/{id}/intervene` 且发送空请求体。陈同学必须改为 `/events/{id}/results` 并发送完整对象。

### 15.4 抓拍终态

`backend/service/alarm_task_service.py` 当前抓拍后固定进入 `WAITING_ALGORITHM`。冷同学必须接入 AlgorithmGateway 或将任务明确结束为 `NO_EVIDENCE/FAILED`，不得长期停留。

### 15.5 人—环境交互尚未进入风险融合

`backend/service/risk_service.py` 当前只将低照度、夜间、重复异常和长期偏离计入 `context_score`，尚未消费 `high_risk_zone_entry` 和 `obstacle_occupancy`。

两周内的最小修复决策：

- 在 `ruleset-v1.0` 中增加有版本记录的 `high_risk_zone` 和 `obstacle_interaction` 上下文因子。
- 只有与可用的 FALL Evidence 同窗出现时才影响工程风险指数；SYSTEM Evidence 不得单独创建橙色或红色事件。
- RuleTrace 必须记录环境因子的 Evidence ID、场景配置版本和分数贡献。
- 增加“相同步态、普通区域”和“相同步态、高风险区域”的对照测试，证明环境只校准风险，不替代人体证据。

## 19. 最终验收场景

### 场景A：正常行为

- 正常起身和常用路线。
- 产生质量合格 Observation，不产生橙色 RiskEvent。
- 可作为经过确认的个人基线候选。

### 场景B：跌倒前兆

- 快速起身后躯干摇摆，并进入人工标定的高风险区域。
- 产生 rapid_rise、trunk_sway 和环境上下文。
- 状态机产生 ORANGE/INTERVENING，智能体解释原因。

### 场景C：恢复

- 干预后老人坐稳，语言或人工反馈为 stable。
- posture_recovered 满足 15 秒稳定要求。
- 60 秒观察期无新危险，事件进入 RESOLVED。

### 场景D：质量失败

- 遮挡、出画、低照度或算法超时。
- 系统产生质量/环境证据或 FAILED，不升级高风险。
- 前端显示失败原因和数据来源。

每个场景必须保存输入素材、请求、响应、RuleTrace、页面截图和运行时间。三段自采视频只用于演示和压力测试，不用于宣称模型准确率。
