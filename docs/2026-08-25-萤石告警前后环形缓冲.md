# 萤石告警前后环形缓冲

## 目标

现有告警 Worker 只能在收到 Webhook 后申请直播地址并启动 FFmpeg，因此可能错过触发告警的动作。环形缓冲 Worker 在授权有效期内持续拉取已经验证的 H.264 HTTP-FLV，将视频切成短期私有分片。收到告警后保存：

```text
告警前 10 秒 + 告警后 20 秒
```

缓冲不可用时，Alarm Worker 自动回退到原有的告警后实时录制，不会因为新增能力阻断告警处理。

## 默认配置

```text
YINGMU_STREAM_BUFFER_ENABLED=true
YINGMU_STREAM_BUFFER_ROOT=
YINGMU_STREAM_BUFFER_SEGMENT_SECONDS=2
YINGMU_STREAM_BUFFER_PRE_SECONDS=10
YINGMU_STREAM_BUFFER_POST_SECONDS=20
YINGMU_STREAM_BUFFER_RETENTION_SECONDS=60
YINGMU_STREAM_BUFFER_RECONNECT_SECONDS=3
YINGMU_STREAM_BUFFER_SELECTION_RETRY_SECONDS=8
YINGMU_STREAM_BUFFER_MAX_ALARM_DELAY_SECONDS=20
YINGMU_STREAM_BUFFER_STALL_SECONDS=8
```

`YINGMU_STREAM_BUFFER_ROOT` 留空时，使用私有媒体目录下的 `.stream-buffer`。私有媒体目录和缓冲目录都必须位于仓库及 OneDrive 之外。缓冲分片不写入数据库，默认约 60 秒自动删除；只有命中告警窗口并通过校验的 MP4 才创建正式 Asset。

## 启动顺序（CMD）

先启动缓冲 Worker：

```cmd
cd /d "<仓库根目录>"
.venv\Scripts\python.exe -m dotenv -f .env run --override -- .venv\Scripts\python.exe -m backend.worker.stream_buffer_worker
```

等待约 12～15 秒，在另一个 CMD 检查是否预热完成：

```cmd
cd /d "<仓库根目录>"
.venv\Scripts\python.exe -m dotenv -f .env run --override -- .venv\Scripts\python.exe scripts\check_stream_buffer.py
```

只有输出中的 `ready` 为 `true` 且 `status` 为 `READY` 时才开始触发告警。随后启动 API、Alarm Worker、Agent Worker 和临时 Webhook 通道。缓冲 Worker 必须始终保持运行。

需要在不保留额外录像的情况下验证分片可拼接性时运行：

```cmd
.venv\Scripts\python.exe -m dotenv -f .env run --override -- .venv\Scripts\python.exe scripts\check_stream_buffer.py --assembly-probe
```

该命令生成临时 MP4、执行 ffprobe 后立即删除，只输出时长、帧率、帧数和字节数。

## 任务判定

- `verification_status=VERIFIED_LIVE_BUFFER_CAPTURE`：使用了告警前后缓冲录像。
- `fallback_kind=SERVER_MANAGED_RING_BUFFER`：Asset 来自环形缓冲拼接。
- `verification_status=VERIFIED_LIVE_CAPTURE`：缓冲不可用，任务使用了原有告警后录制回退。
- 任务摘要 `capture.mode=RING_BUFFER`：使用了完整环形缓冲。
- 任务摘要 `capture.mode=DIRECT_FALLBACK`：缓冲失败后使用告警后录像；`buffer_error_code` 给出脱敏原因。
- Worker 日志出现 `stream_buffer_fallback`：只输出任务 ID 和脱敏错误码，不包含播放地址、设备序列号或私有路径。

## 隐私与运行边界

- 仅在授权人员、授权机位和授权保留期限均有效时运行。
- 缓冲目录不得进入 Git、OneDrive、日志、截图或提交材料。
- 停止现场采集后应同时停止缓冲 Worker，并确认短期分片按保留周期清理。
- 直播地址、Token、验证码、设备序列号和完整私有路径不得写入验收报告。
- 当前实现每台配置设备保持一个直播连接；断流后自动重新申请临时播放地址并重连。
- FFmpeg 即使没有退出，只要 8 秒没有生成新分片，也会被视为卡流并自动重连。
- 单个已完成分片只表示 `WARMING`；只有最新完整分片之前具备连续 10 秒覆盖时才会进入 `READY`。
- 同一设备只允许一个缓冲 Worker；重复启动会返回 `STREAM_BUFFER_WORKER_ALREADY_RUNNING`。
- 窗口选择拒绝丢失分片、过大间隙和重叠会话，不能用表面时长掩盖断流。
- Worker 在启动和运行期间持续校验授权；授权缺失或到期时停止采集，不再自动重连。

## 验收

触发一次受控动作后，检查：

1. 告警任务为 `COMPLETED`。
2. Asset 为 `LIVE_DEVICE`、`simulated=false`、`VERIFIED_LIVE_BUFFER_CAPTURE`。
3. ffprobe 显示 H.264、正常帧率、约 30 秒可播放视频。
4. 录像同时包含告警前动作和告警后画面。
5. GAIT/TRAJECTORY 正常返回，Evidence、RiskEvent 和事件证据关联按规则生成。
6. 缓冲工作区和超过 60 秒的分片已清理。

正式验收要求连续 3 次受控告警均满足以上条件。授权人员不需要真实跌倒；只需全身入镜完成受控起身/摆动，触发后继续自然走动至少 20 秒。
