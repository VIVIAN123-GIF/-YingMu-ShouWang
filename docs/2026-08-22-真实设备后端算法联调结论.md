# 2026-08-22 真实设备后端算法联调结论

## 结论摘要

2026-08-22 已完成一轮真实设备告警联调，确认以下链路可用：

```text
真实设备告警
  -> 萤石消息推送
  -> 临时 HTTPS 通道
  -> POST /api/v1/webhooks/ezviz
  -> RiskAlarm / AlarmProcessingTask
  -> HLS 临时播放地址
  -> FFmpeg 私有 MP4

```

本轮不能认定为完整风险闭环。TRAJECTORY 正常完成并返回 `NO_EVIDENCE`；GAIT 返回
`FAILED / FEATURE_INPUT_INVALID`，脱敏复核原因是 `no_pose_detected`。因此没有新增
Evidence、RiskEvent 或 Agent Job。

统一口径：真实设备到算法调用和 Observation 入库已跑通；算法业务验收、风险事件和
Agent 链路尚未完成。

GAIT 的最终输入门槛；算法方仍需确认最低时长、FPS、有效姿态帧数和拍摄条件。

FFmpeg 通过 winget 安装后，已经运行的 PowerShell 和后台 Worker 可能继承旧 `PATH`。
部署时应在同一启动环境验证 `YINGMU_FFMPEG_BINARY` 可解析，必要时使用绝对路径。

失败，不得批量修改历史任务状态。

## 未完成项

1. GAIT 必须对正常授权视频返回 `NO_EVIDENCE` 或符合合同的 `LOW_QUALITY`，不能返回
   `FEATURE_INPUT_INVALID`。
2. 算法方需要明确 `no_pose_detected` 的拍摄条件和最低输入门槛。
3. 需要用授权受控风险样本生成至少一条 Evidence，并验证 RiskEvent、RuleTrace 和 Agent Job。
4. 需要验证同一任务重试时 Observation/Evidence ID 稳定且数据库无重复写入。
5. HLS 真实告警采集仍出现前两次失败、第三次成功，生产部署前需要补充连续多轮稳定性测试。
6. 萤石服务端语音能力仍未实机验证。

## 安全与隐私

- 临时通道地址会随进程重启变化，平台回调配置必须在每轮现场测试前复核。
- 不在文档或报告中保存临时播放 URL、Token、设备序列号、验证码或 `.env` 内容。
- 临时媒体探测只保留脱敏 JSON，诊断 MP4 自动删除。
- 真实告警媒体保存在仓库和 OneDrive 之外的授权私有目录，并执行保留期限控制。
- 曾通过聊天或临时终端传递的隧道认证值应撤销并轮换，不得继续作为长期凭证使用。
- 禁止要求测试人员真实跌倒；风险样本使用授权回放或有软垫和保护人员的受控动作。
