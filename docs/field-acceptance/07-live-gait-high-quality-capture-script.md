# LIVE_DEVICE 高质量 GAIT 联调拍摄脚本

适用范围：已授权健康成年人的真实萤石设备联调。目标是获得一条 `LIVE_DEVICE/simulated=false` 的高质量姿态输入，验证 GAIT 和 TRAJECTORY 的工程处理链路。本脚本不是医学评估，不实施真实跌倒、绊倒、闭眼行走或失控动作。

## 1. 通过口径

| 项目 | 现场目标 | 最低接受线 |
|---|---:|---:|
| 有效姿态帧比例 `valid_frame_ratio` | `>= 0.85` | `>= 0.65` |
| 人体关键部位 | 头、肩、髋、膝、踝、双脚全程可见 | 不得持续缺失 |
| GAIT | `SUCCESS` 或可解释的 `NO_EVIDENCE` | 不得为 `FAILED` 或 `LOW_QUALITY` |
| TRAJECTORY | `SUCCESS` 或可解释的 `NO_EVIDENCE` | 不得为 `FAILED` 或 `LOW_QUALITY` |
| 任务与素材 | `COMPLETED`、`RING_BUFFER`、`LIVE_DEVICE` | Asset 可用且 `simulated=false` |

`valid_frame_ratio < 0.65` 会被 GAIT 视为输入质量不足。现场把目标定为 `0.85`，为编码抖动、短时转身和检测波动留出余量。

## 2. 角色与安全边界

- 参与者：已授权、无头晕疼痛或行动不适的健康成年人。
- 安全员：站在画面外侧后方，保持伸手可及，不进入走动路线。
- 记录员：负责计时、观察画面完整性、记录实际告警时间与任务结果。
- 任何人说出“停止”，或出现头晕、疼痛、真实失衡、碰撞风险时，立即停止；该次标为 `ABORTED`，当天不再强行重试。
- 不做真实跌倒、假摔、绊脚、闭眼行走、急转、交叉脚、突然冲刺或由安全员拉拽参与者。

## 3. 开机前 5 分钟检查

1. 确认 FastAPI、Alarm Worker、Agent Worker、Stream Buffer Worker 与 HTTPS Tunnel 都在运行。
2. 执行 `python -m scripts.check_stream_buffer --assembly-probe`；必须看到 `ready=true` 和 `SUCCESS`。
3. 在萤石客户端确认摄像头在线、画面可预览、H.264 已启用、告警推送已开启。
4. 固定机位：镜头高度约 1.0-1.3 米；使用横向画面；关闭云台跟踪、巡航、自动变焦和数字变焦。
5. 在地面贴三条标记：左起点、中央动作区、右终点。步行路线保持 3-5 米，全部位于画面内。
6. 参与者站在中央时，身体高度占画面高度约 55%-80%；头顶和鞋底均留有余量。
7. 调整照明，避免背光、门窗强光、频闪、反光地面和深阴影。衣物与墙面、地面形成明显对比；穿防滑鞋，不穿拖鞋、高跟鞋、拖地裤或与背景同色的服装。
8. 录制或预览 10 秒：逐项确认头、肩、髋、膝、踝和双脚没有出画；确认画面中仅有一名主要参与者。

若第 8 步不合格，先调整机位、构图或照明；不要触发真实告警。

## 4. 正式受控告警脚本

本项目环形缓冲保留告警前 10 秒、告警后 20 秒。因此参与者在告警前后都必须保持全身可见，不得等待告警后才进入画面。

| 相对告警时间 | 参与者动作 | 记录员口令与检查 |
|---|---|---|
| `T-12` 至 `T-8` 秒 | 站在中央动作区，自然站稳，双脚平行、双手自然下垂 | “保持站稳，头和脚都在画面内。”检查全身完整入镜。 |
| `T-8` 至 `T-2` 秒 | 以舒适正常步速从中央向右走 3-4 步，再自然回到中央 | “正常走，不加速，不看镜头。”双脚不得被家具或安全员遮挡。 |
| `T-2` 至 `T+3` 秒 | 在中央自然站立，轻微正常重心调整即可 | 此时应由已开启的正常移动/智能检测产生真实 `ys.alarm`。记录员记录平台告警显示时间。 |
| `T+3` 至 `T+10` 秒 | 从中央向左走 3-4 步，再回到中央 | “继续正常走，步幅舒适。”保持正面或前侧约 30-45 度朝向。 |
| `T+10` 至 `T+25` 秒 | 在中央自然稳定站立，可缓慢转头；不转身离开、不蹲下、不挥舞 | “站稳，保持完整入镜。”这是后置缓冲和算法稳定帧的关键区间。 |
| `T+25` 至 `T+35` 秒 | 继续自然站立，等待任务完成 | 记录员确认没有第二个人进入画面、没有遮挡或云台转动。 |

如平台告警发生得比预期早或晚，参与者不要突然改变动作：继续在中央区域以自然步速走 6-8 步后，稳定站立至少 20 秒。记录员按平台实际告警时间登记，而不是按口令时间补写。

## 5. 拍摄人员口令卡

```text
准备：请站在中央，头顶和双脚都留在画面里。
开始：自然走到右侧，再回到中央。不要看镜头，不要加速。
保持：自然站稳，等待告警。
继续：自然走到左侧，再回到中央。
结束动作：保持站稳二十秒，双脚不要出画。
停止：如有任何不适或安全员喊停止，立刻原地站稳或坐到安全椅上。
```

## 6. 每次告警后的 2 分钟核查

1. 平台、Tunnel 与 FastAPI 日志均出现真实 `POST /api/v1/webhooks/ezviz`，并返回 HTTP `200`。
2. 查询 `GET /api/v1/alarms/processing`；任务应依次达到 `COMPLETED`，且 `attempt_count=1`。
3. 核对 `capture.mode=RING_BUFFER`，`capture_asset_id` 非空。
4. 核对 Asset：`source_mode=LIVE_DEVICE`、`simulated=false`、`verification_status=VERIFIED_LIVE_BUFFER_CAPTURE`、视频可用。
5. 核对算法：GAIT、TRAJECTORY 的状态、耗时和错误码；同时记录 Observation 与 Evidence 数量。
6. 任务为 `COMPLETED` 但任一模块为 `LOW_QUALITY` 或 `FAILED` 时，记录为 `DEGRADED_RETRY`，并检查画面质量；不得把结果写成完整通过。

## 7. 可重拍与不可选择性重拍

允许以新的告警任务重新采集的技术原因：头或双脚持续出画、主要关节被遮挡、第二人遮挡、云台移动、画面严重过暗/逆光、视频损坏、摄像头掉线、Buffer 未就绪、任务基础设施失败。

不得因为算法没有产生预期风险结论而选择性删除或修改一条画面合格的记录。画面合格但算法为 `NO_EVIDENCE`、`LOW_QUALITY` 或出现保守 `YELLOW/REVIEW` 时，保留该记录和实际结果；下一次改进机位或光照时使用新的任务和新的台账记录。

## 8. 连续验收要求

在机位、分辨率、帧率、照明和服装条件冻结后，连续执行 3 次。只有 3 次均满足：真实 Webhook `200`、任务 `COMPLETED`、`RING_BUFFER`、真实视频 Asset、GAIT 与 TRAJECTORY 均非 `FAILED/LOW_QUALITY`，才可标记为完整实时算法工程验收通过。
