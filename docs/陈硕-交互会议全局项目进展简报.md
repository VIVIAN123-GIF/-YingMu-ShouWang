## 一句话结论

目前项目已经完成统一方案、四对象数据契约、Mock/HTTP 后端、Vue 家属端和姿态/语音行为最小 Demo，跌倒风险的模拟闭环可以稳定复现；陈硕负责的前端页面、接口适配、反馈交互、来源标识、演示模式和验收材料已基本完成。

但全局项目还不能表述为“真实设备和真实算法已经完成闭环”：真实萤石资源、行为算法正式接入、实测指标、实验材料和最终路演材料仍是主要缺口。

### 2. 跌倒事件主链路展示

- 首页展示当前安全水位和近期风险事件。
- 事件列表支持风险方向、等级、状态和输入来源筛选。
- 事件详情展示 Evidence 摘要、Observation 追溯、风险趋势、干预时间轴和工具结果。
- 支持后端状态自动轮询和页面同步：

```text
INTERVENING → OBSERVING → RESOLVED
```

  - 调用 `POST /api/v1/events/{event_id}/results`；
  - 使用稳定结果 ID和 `Idempotency-Key`；
  - 重复提交复用第一次结果；
  - 前端不会直接把事件改成 `OBSERVING` 或 `RESOLVED`。

## 四、当前主要挑战

### 1. Mock 成果与真实闭环的边界

当前最容易被误解的是：前后端 HTTP 联调已经完成，但多数证据和工具仍标记为 `MOCK` 或 `RECORDED_REPLAY`。会议中应明确说“系统闭环已验证”，但不能说“真实摄像头跌倒识别已完成”。

### 2. 真实设备和凭证不稳定

当前 C6c 的 App 画面可用，但开放平台凭证、设备在线状态、抓图和临时播放地址仍存在阻塞。旧凭证不能继续使用，实机测试还需要设备、网络和授权素材协调。

### 3. 行为算法尚未达到正式可用程度

常易铭的语音/行为 Demo 可以复现，但人工区域标定、房间转换、访客停留、多日趋势和实时输出尚未全部接入统一后端，阈值仍是演示或未标定值。

### 4. 实测指标和材料一致性

代码、PPT、视频、研究报告和验收日志必须使用同一套状态、规则版本、来源标签和指标口径。任何把模拟数据写成实测结果的表达都会造成验收风险。

### 5. 隐私与适老化约束

不能共享主账号、AccessToken、家庭 IP 或永久视频地址；心理和诈骗页面必须保持低打扰、非诊断表述，并提供模拟水印和授权说明。

## 五、建议在会议上向老师确认的问题

1. 最终演示是否采用“真实跌倒 + 心理/诈骗明确模拟回放”的组合？
2. 在萤石语音、消息或临时播放能力未开放时，是否接受“失败日志 + Mock 降级”的展示方式？
3. 8 月 21 日实验验收的最小指标集合是什么：准确率、误报率、漏报率、延迟、送达率还是连续运行时长？
4. 100 天故事回放需要完整视频，还是允许以授权片段占位 + 事件时间轴作为第一版？
5. 最终材料是否统一以 `ruleset-v1.0` 和四对象 v1.0 契约作为唯一口径？
