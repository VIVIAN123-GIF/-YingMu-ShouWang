## 四、GAIT 最低时长 / FPS / 帧数 / 拍摄要求

| 输入项 | 硬性要求 | 说明 |
|---|---|---|
| 视频容器 | `.mp4`（也支持 `.avi/.mov/.webm`） | 见 `SUPPORTED_VIDEO_INPUTS` |
| 时长 | **最低 5s**，推荐 15–30s | 起身场景至少 8s（含坐姿 2s + 起身 + 站稳 5s） |
| fps | **最低 10**，推荐 15 或以上 | 低于 10 fps 会影响摆动频率与相对步速计算 |
| 分辨率 | **最低 720p**，推荐 1280×720 | 关键点可见度低于 0.65 会被判 `LOW_QUALITY` |
| 有效姿态帧比例 | ≥ 0.65 | 否则输出 `tracking_lost` Evidence 与 `LOW_QUALITY` 状态 |
| 关键点可见度 | 核心 6 点均值 ≥ 0.70 | 肩、髋、脚踝 |
| 画面内容 | 单人全身入画 | 多人同框会导致目标不稳，规则口径为已知边界 |
| 光照 | 正常室内光照 | 低照度当前只做降级不报警 |
| 输入介质 | 授权本地 MP4 | `source_mode=RECORDED_REPLAY`、`simulated=true`、`AUTHORIZED` |

### 5.4 状态取值与含义

| status | 触发条件 | 后端处理建议 |
|---|---|---|
| `SUCCESS` | 有观测且触发至少一条 Evidence | 正常提交风险引擎 |
| `NO_EVIDENCE` | 有观测但未触发 Evidence | 记录为正常动作，不入 RiskEvent |
| `LOW_QUALITY` | `valid_frame_ratio<0.65` 或核心可见度不足 | 输出 `tracking_lost`，不参与升级 |
| `FAILED` | 输入非法或异常 | `error.code` 见下 |

### 5.5 错误码

| error_code | 含义 |
|---|---|
| `MODEL_NOT_FOUND` | `model_path` 不存在 |
| `INPUT_MISSING` | `media_locator` 空 |
| `INPUT_NOT_FOUND` | 文件不存在 |
| `UNSUPPORTED_INPUT` | 后缀不在支持列表 |
| `VIDEO_ANALYSIS_FAILED` | 视频无法解码 |
| `EMPTY_FEATURES` | 视频无可用帧 |
| `ALGORITHM_EXCEPTION` | 其他兜底 |

## 六、幂等重试与脱敏归档

**幂等**：
- `job_id` 由后端生成并保证唯一，同 `job_id` 重复调用返回同一 AdapterBatch 结构（但内部 `observation_id`/`evidence_id` 用 SHA-1(job_id+feature+timestamp) 稳定生成）。
- 重复提交 Evidence 时后端应命中 `R-SYSTEM-01` 幂等规则（已在 `run_recorded_replay_acceptance.py` 中验证）。

**重试**：
- 网关侧由 `backend/service/algorithm_gateway.py::AlgorithmGateway.run` 处理（默认 timeout=8s，max_retries=2，backoff 0.2s/0.5s，熔断阈值 3 次）。
- 适配器**只在遇到 TimeoutError/ConnectionError/OSError 时重试**，业务错误（`AlgorithmInputError`）不重试。

**脱敏归档**：
- `AdapterBatch.diagnostics` 与 `error.message` 使用 `_redact_reference()`，URL 显示为 `<redacted_url>`，本地路径显示为 `<redacted>`；
- 不写入用户名、设备序列号、Token、临时 URL；
- `source_mode` 必须为 `RECORDED_REPLAY`，`simulated=true`；
- 归档路径建议：`artifacts/2026-08-24_gait_integration/{job_id}/adapter_batch.json`。

## 八、联调不通过时的兜底路径

如现场出现 GAIT 无法从 MP4 直读特征的问题，赵同学可即时切换至"预计算特征 JSON"路径：

1. 使用 `deliverables/zy/pose-demo/scripts/recorded_replay_adapter.py` 预先跑一次姿态提取；
2. 输出 `features.json`（结构见 `tests/test_gait_adapter.py::_write_features`）；
3. `AlgorithmJob.media_type` 改为 `gait_feature_json`，`media_locator` 指向该 JSON；
4. 适配器改走特征 JSON 分支，不再解码视频，可以避开 mediapipe 环境差异。

这条兜底路径已在单元测试中验证，联调现场可直接切换。
